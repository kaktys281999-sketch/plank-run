## 2. Итоговое решение и почему

### 2.1 Вердикт трёх судей (`PLAN.md:580-585`)

Оценки подтверждаются в самих судьях: масштаб `plan/backend-judge-scale.md:5-24`, безопасность `backend-judge-security.md:5-27`, скорость `backend-judge-velocity.md:5-34`.

### 2.2 Гибрид (`PLAN.md:587`)

Все три судьи независимо рекомендовали гибрид.
- Данные и протокол из C. Устройство главное, гость без аккаунта, офлайн по умолчанию, здоровье не покидает устройство, курсор на пользователя.
- Сервер и эксплуатация из A. Один Docker-образ, Postgres единственное состояние, ячейки по регионам, периметр безопасности.
- Дисциплина из B без самого Supabase. Тесты авторизации, линтер приватности, правила правдоподобия, алерты.
- Ревью плана урезало гибрид. Без HLC, без билетов и пересимуляции, S1 без managed PG (`PLAN.md:587`).

Версии гибрида у каждого судьи: масштаб `backend-judge-scale.md:101-126`, безопасность `backend-judge-security.md:73-96`, скорость `backend-judge-velocity.md:142-165`.

### 2.3 Почему сервер не сразу (`PLAN.md:589-595`)

- Видео, ML, игры, план и прогресс живут на устройстве. Серверу остаётся аккаунт, второе устройство и бэкап, друзья, компании, вызовы, правдоподобие счёта (`PLAN.md:591`).
- Нагрузка. 100k MAU × 8 сессий в месяц около 0,3 сессии в секунду, с pull раз в 60 с при открытом окне около 3-10 запросов в секунду (`PLAN.md:591`).
- «Белые списки». Около двух третей мобильных сессий в Центральной России летом 2026 по данным Vigo, недоступен любой сайт вне перечня, включая российский. Доступность даёт только офлайн-PWA (`PLAN.md:591`; первоисточник `research/verify-backend-compliance.md:32`).
- Триггер сервера (Этап 4). Друзья попросили второе устройство, бэкап или общий рейтинг (по опыту через 4-6 недель альфы) и выбран регион ячейки. Если триггер сработает раньше конца Этапа 3, B1 и минимальный B2 обгоняют его. До того мостики это ссылки-вызовы и экспорт/импорт файла. До B0.5 стоимость $0 (`PLAN.md:593`).
- Регион решается по частям. Зеркало статики, моделей и аудио после Этапа 0 по скорости загрузки у друзей. Страна VPS для B0.5 по аудитории беты. Ячейка данных на B1. Вопросы §14 п. 1-2 (страны друзей, статус владельца) закрыть к концу альфы (`PLAN.md:595`).

## 3. Что отклонено и причины

### 3.1 Supabase (вариант B), `PLAN.md:597`

- Free засыпает через 7 дней тишины и без бэкапов. Pro $25 при нулевом доходе.
- PITR требует compute Small, около $130 в месяц.
- Нет региона в РФ, нельзя оплатить российской картой, self-hosted это около 11 контейнеров и вторая модель безопасности.
- Схема открыта через PostgREST, ошибка RLS в ИИ-миграции молча открывает данные.
- Токены по умолчанию в `localStorage`.
- Обещанной в плане B экономии 3-5 недель не видно (`backend-judge-velocity.md:87`: реальная экономия 1-2 недели).

Подробности по B у судей.
- Масштаб: статика на GitHub Pages или Cloudflare, при троттлинге до 16 КБ на ресурс первая загрузка 13,5 МБ WASM и моделей не пройдёт (`backend-judge-scale.md:63`). Курсор `server_seq` с триггером имеет проблему порядка коммитов, строки будут пропадать из pull (`backend-judge-scale.md:65`). Привязка к Supabase в SQL: `realtime.send()`, `storage.foldername`, Vault (`backend-judge-scale.md:66`). Realtime на Pro 500 одновременных соединений (`backend-judge-scale.md:69`).
- Безопасность: PostgREST по умолчанию выдаёт права `anon` и `authenticated` на новые таблицы (помечено звёздочкой, из знаний модели), упомянут CVE-2025-48757 (звёздочка) (`backend-judge-security.md:50`). Аноним получает роль `authenticated` (`backend-judge-security.md:51`). Самодельный OAuth-мост `generateLink` → `verifyOtp` (`backend-judge-security.md:53`). Модерация через Studio с правами суперпользователя минуя `audit_log` (`backend-judge-security.md:56`).
- Скорость: ловушка Free и ловушка PITR (`backend-judge-velocity.md:95-96`), пять рантаймов (`backend-judge-velocity.md:97-102`), скрытые строки счёта custom domain около $10, Branching около $10, Large compute около $110, все три цифры н/п (`backend-judge-velocity.md:108`).
- Проверенные цены Supabase: Free 50 000 MAU, 500 МБ БД, 5 ГБ egress плюс 5 ГБ cached egress, 1 ГБ файлов, 2 проекта, пауза после недели. Pro 100 000 MAU, затем $0.00325 за MAU, 250 ГБ egress, $10 compute credits (`research/verify-backend-compliance.md:46`, первоисточник `plans.ts` репозитория Supabase). PITR $0.137/ч около $100 в месяц за 7 дней, пример Pro + Small + PITR 7 дней = $25 + $15 + $100 − $10 = $130 (`verify-backend-compliance.md:47`). Кастомный OIDC с апреля 2026, лимит 3 кастомных провайдера на проект (`verify-backend-compliance.md:48`).
- Что из B берётся: тесты прав доступа (pgTAP или на Testcontainers), линтер приватности схемы, алерты в Telegram, доска друзей до готовности пересимуляции (`backend-judge-velocity.md:81-84`, `162`), конкретные правила правдоподобия (`backend-judge-security.md:89`).

### 3.2 Монолит A как целое

- Курсор pull: глобальный `updated_seq` и «безопасный горизонт 2 с», транзакция длиннее 2 с даёт пропуск строки (`backend-judge-scale.md:47`; описание у A `plan/backend-option-a-monolith.md:187`).
- `progress.plans.items jsonb` и `sessions.rpe` на сервере, косвенные данные о здоровье, ссылка на C-184/20 и C-21/23 (`backend-judge-scale.md:49`, `backend-judge-security.md:41`; сама таблица `backend-option-a-monolith.md:103,108`).
- `GET /v1/analyses/file_sha256/{h}` передаёт серверу хеши пользовательских треков (`backend-judge-scale.md:50`; `backend-option-a-monolith.md:143`).
- Для `GET /v1/ghosts/{session_id}` проверка доступа не описана, риск IDOR (`backend-judge-security.md:42`).
- При `rejected` клиент удаляет операцию из outbox, возможна тихая потеря (`backend-judge-security.md:43`; `backend-option-a-monolith.md:178`).
- Учения по восстановлению в GitHub Actions для RU это обработка ПДн на иностранном раннере (`backend-judge-security.md:44`).
- Ротация 7/4/6 и отсутствие журнала удалений, удалённые пользователи воскреснут после восстановления (`backend-judge-security.md:45`).
- Лишняя для одного человека обвязка: dependency-cruiser, oasdiff, sops+age, мультиарх-образы, npm-алиасы, Kamal (`backend-judge-velocity.md:65-72`). В Ф2 заложены 2-3 api за балансировщиком, PG HA, PgBouncer, Valkey при нагрузке около 0,3 RPS (`backend-judge-velocity.md:73`).
- M0 «около 1 недели» занижена: `js/games/fireflies.js` 14 раз обращается к `Math.random` и времени, перевод на детерминированную симуляцию 2-3 недели (`backend-judge-velocity.md:62`).

### 3.3 Local-first целиком (вариант C)

- Противоречие по наградам: «не пересчитываются» против «сервер пересчитывает всё сам» (`backend-judge-scale.md:94`; `backend-judge-security.md:59`; в C `backend-option-c-local-first.md:120` и `281`). Решение плана: сервер считает (`PLAN.md:605`).
- `users.id = localUserId`, id аккаунта выбирает клиент (`backend-judge-security.md:60`; `backend-option-c-local-first.md:198`). Решение плана: `user_id` выдаёт сервер (`PLAN.md:605`).
- Журнал `user_events` растёт на 2-3 ГБ в месяц, срок хранения не задан (`backend-judge-security.md:61`, `backend-judge-scale.md:95`, `backend-judge-velocity.md:129`). У A около 0,4 ГБ в месяц (`backend-judge-velocity.md:129`, `backend-option-a-monolith.md:73`).
- Debug-экспорт захватит таблицу `health` (`backend-judge-security.md:62`).
- Cookie на `api.` рядом с `app.` требует CORS с credentials (`backend-judge-security.md:63`).
- Нет РКН, согласия на распространение (ст. 10.1), гейта 16+, DPIA, MFA админки, модерации ников, управления секретами (`backend-judge-security.md:64`).
- Event sourcing как «постоянный налог», при этом общих изменяемых данных нет (`backend-judge-velocity.md:128`). «Около 1,5 тыс. строк» на sync оценено оптимистично, с тестами 3-5 тыс. строк (`backend-judge-velocity.md:120-127`).
- Ни одна веха C не оценена по срокам (`backend-judge-velocity.md:119`).
- Правило «первая общая изменяемая сущность → PowerSync» слишком грубое, компании из M3 запустят его сразу (`backend-judge-scale.md:96`).
- Тай-брейк рейтинга друзей требует событие `plan_summary {sessionsPerWeek}` (`backend-judge-scale.md:97`), в плане `plan_summary` есть (`PLAN.md:617`).

### 3.5 Другие платформы из `research/backend.md:16-35`

- Firebase отклонён: NoSQL плохо ложится на лидерборды, максимальная привязка, сервисы Google под риском в РФ (строка 30). Auth сверх 50k MAU около $275 только за Auth на 100k MAU (строка 226).
- Convex отклонён: логика под его рантайм, выход означает переписать бэкенд (строка 31).
- Appwrite Cloud Free не годится: пауза после 7 дней без активности в консоли, удаление через 90 дней паузы (строки 32, `verify-backend-compliance.md:49`).
- PocketBase годится для фазы «я и друзья», но масштабируется вертикально, pre-1.0 (v0.40.5), переезд требует миграции SQLite→Postgres (строка 33).
- Cloudflare edge технически идеален для дуэлей и раздачи музыки, но в РФ трафик к CF режут, D1 упирается в 10 ГБ на базу (строка 34).
- Lucia v3 deprecated, пакет 3.2.2 (`research/backend.md:94`, `verify-backend-compliance.md:54`). Auth.js с сентября 2025 в режиме патчей под Better Auth, v5 осталась beta (`verify-backend-compliance.md:52`).
- Better Auth: куплен Vercel 07.07.2026, MIT, версия 1.7.11 на 19.10.2026 (`verify-backend-compliance.md:53`).
- Прочие версии на 19.10.2026: drizzle-orm 0.45.4 (rc 1.0.0-rc.4), prisma latest 8.0.0-rc.23, pg-boss 12.38.0, hono 4.13.13 (`verify-backend-compliance.md:57`).

## 5. Протокол синхронизации (`PLAN.md:629-635`)

- Push `POST /v1/sync/push` (до 200 записей и 512 КБ): в одной транзакции zod-валидация, `insert … on conflict (id) do nothing` (тот же id с другим хэшем даёт `id_conflict`), проекции, задачи pg-boss. Ответ: статус каждой записи и `user_seq`. Отклонённые записи клиент не удаляет, а держит в карантине с причиной. Реплеи `PUT /v1/replays/{id}` до 64 КБ с проверкой sha256, только по действию игрока (вызов, призрак).
- Pull `GET /v1/sync/pull?after=<user_seq>` возвращает записи других устройств и сервера, `minClientV`, `contentVersion`, `server_epoch`. Bootstrap: `user_state` и 50 последних сессий.
- Когда синхронизироваться: старт, `online`, возврат на вкладку, конец сессии, раз в 60 с при видимом окне. Один агент на все вкладки (Web Locks). Background Sync не используется, в Safari его нет.
- Слияние: сессии объединение, XP и камни сумма (считает сервер), звёзды и рекорды максимум, разблокировки объединение (двойная покупка возвращает цену), настройки LWW по полю в порядке приёма сервером (время клиента только для показа, будущее зажимается до +5 мин), уровень последняя принятая смена с проверкой «+3 в неделю», план и анкета не синхронизируются (на новом устройстве короткая анкета, §6.4), ник только онлайн.
- Совместимость и тесты: сервер принимает версии v и v−1, по `minClientV` экран «Обновите приложение» без потери outbox, БД по схеме expand → backfill → contract. Property-тесты свёртки и симулятор синхронизации (клиенты на fake-indexeddb, Postgres в Testcontainers, обрывы до и после коммита).
- `server_epoch` объясняется судьёй масштаба: без него обещание «клиенты сами дозагрузят данные» не работает, так как подтверждённые события клиент повторно не отправляет, а новое устройство получает только снимок и последние 50 сессий (`backend-judge-scale.md:33`).
- Почему курсор на пользователя: глобальный `bigserial` теряет строки, когда транзакция с меньшим номером коммитится позже (`backend-option-c-local-first.md:142`).
- Правила слияния варианта C с HLC (до D21) `backend-option-c-local-first.md:168-184`. D21: без HLC, LWW по полю в порядке приёма сервером, так как конфликты только между устройствами одного человека (`PLAN.md:123`, `142`).
- Лимиты варианта C: событие до 8 КБ, батч до 200, реплей до 64 КБ, возраст события до 90 дней (`backend-option-c-local-first.md:282`).
- Retry при 426/rejected: судья scale отмечает, что судьба outbox у A при ответе 426 не определена (`backend-judge-scale.md:51`).
- Оценка размера собственного протокола около 1,5 тыс. строк (`backend-option-c-local-first.md:9`), по судье скорости с тестами 3-5 тыс. (`backend-judge-velocity.md:127`).

## 7. Ячейки по регионам

- Ячейка это один образ + `.env` (`CELL=ru|global`, `ROLE=api|worker|all`). Выбирается по стране проживания при регистрации, не по IP. Друзья и компании внутри ячейки. Межрегиональное позже, для RU это трансграничная передача с согласием и уведомлением РКН (`PLAN.md:665`).
- Открытый вопрос юристу: ч. 5 ст. 18 152-ФЗ говорит о гражданах РФ, а ячейка выбирается по проживанию. Куда относить гражданина РФ за рубежом. До ответа спрашивать о гражданстве РФ или отправлять в RU-ячейку всех, кто указал Россию или номер +7 (`PLAN.md:665`).
- Статика, модели, аудио для РФ с российского хостинга под тем же hostname, без Cloudflare и jsDelivr (`PLAN.md:666`).
- Один hostname статики, чтобы IndexedDB гостя не зависела от страны. Со второй ячейкой два зеркала статики за GeoDNS, API на `ru.api.<домен>` и `eu.api.<домен>`, cookie `__Host-` на хосте API, CORS на один origin (`PLAN.md:607`).
- Проблема origin: IndexedDB, OPFS, cookie и push-подписка привязаны к origin. Гость, установивший глобальный PWA и выбравший «Россия», при разных доменах потеряет локальный прогресс. Судья масштаба: ни один вариант этого не решает (`backend-judge-scale.md:31`). Запасной план судьи: разные домены и явный «перенос гостя» по коду или файлу (`backend-judge-scale.md:115`).
- Проверить до решения: как GeoDNS с одним hostname работает под белыми списками. Если зеркала нет в перечне, остаётся только офлайн (`backend-judge-scale.md:131`).
- Перенос пользователя между ячейками. У A «минуты» (`backend-option-a-monolith.md:325`). Судья масштаба: это игнорирует VAPID-ключи у каждой ячейки (push-подписки пересоздаются), дружбы обрываются на границе ячеек, меняется origin (`backend-judge-scale.md:53`). У C это экспорт журнала, импорт в новой ячейке, удаление в старой (`backend-option-c-local-first.md:319`).
- Telemetry гостя в РФ: ошибки должны уходить в GlitchTip того зеркала, с которого загружена статика (`backend-judge-scale.md:32,114`). В плане: до B0.5 только кнопка «Отправить отчёт» (файл JSON), с B0.5 GlitchTip и `/telemetry` на VPS беты, для указавших Россию выключены до RU-ячейки и уведомления РКН. На российском зеркале до тех пор логи без IP (`PLAN.md:666`).
- Хостинги для RU по документам: Timeweb Cloud, Selectel VPS (Ф0), Yandex Compute + Managed PostgreSQL + Object Storage + CDN (Ф1), Yandex Cloud NLB, MDB HA, CDN (Ф2) (`backend-option-a-monolith.md:67`). Yandex Cloud цены +5-8% с 01.05.2026 (`research/backend.md:47`).
- Казахстанскую ячейку заранее не строить (`PLAN.md:734`; `backend-option-a-monolith.md:72`).

## 10. Чек-лист безопасности и приватности (до открытия входа)

Версия плана (`PLAN.md:687-694`), восемь пунктов.

1. Приватность. Здоровья нет ни в сетевых схемах, ни в breadcrumbs, ни в debug-экспорте, ни прямо, ни косвенно (поля §10.4, тест «бережный маршрут неотличим»). На сервере только вход, ник, возрастная группа, уровень, итоги без вариаций, `plan_summary`, друзья, согласия. Реплеи только отправленные игроком, логи 14 дней, компактация журнала, неактивные удаляются через 24 месяца. CSP `connect-src` только свои хосты.
2. Доступ. Cookie `__Host-`, `Origin`, отзыв сессий. Матрица авторизации в CI на каждый эндпоинт (A, B, аноним, забаненный, удалённый). RLS как страховка через `SET LOCAL app.user_id`. Роли БД `app`, `migrator`, `readonly`, `backup`. Postgres не виден снаружи.
3. Злоупотребления. Гейт 16+ (в RU-ячейке до ответа юриста 18+ или согласие родителя). Фильтр ников RU/UZ/EN. Жалобы, блоки, теневой бан. Никакого свободного текста.
4. Правдоподобный счёт. Награды на сервере из фактов, проверка правдоподобия, лимиты (до 20 сравниваемых сессий в день), не больше одной звезды «Сделано» за раннюю остановку в недельном рейтинге. HMAC, билеты и пересимуляция только с публичными досками (B3).
5. Право. Уведомление РКН до любой обработки ПДн россиян (вход, телеметрия, логи с IP, отчёты). Согласия с версиями. Для RU отдельное согласие на обработку.
6. Потеря данных. Клиент: `persist()`, установка, экспорт, карантин отклонённых. Сервер: бэкапы в стране ячейки, учения, журнал удалений.
7. Секреты. sops + age с ключом на ячейку, контейнер не от root, Renovate, поиск секретов в репозитории и бандле.
8. Инциденты. Runbook: РКН в течение 24 и 72 часов (н/п), надзорный орган GDPR в течение 72 часов, смена ключей, письмо пользователям.

## 12. Требования права по странам

Общая оговорка: это не юридическая консультация, нужен местный юрист перед запуском в стране и медик перед альфой и бетой (`PLAN.md:712`; `research/compliance.md:3`). Проверка в research проводилась по поисковым сводкам, тексты 199-ФЗ и 149-ФЗ напрямую открыть не удалось (`research/verify-backend-compliance.md:5`). Звёздочка (\*) и «н/п» в документах значат непроверенное. Дата проверки этих фактов в самих документах 19.10.2026.

### 12.1 Какие данные что значат (`PLAN.md:714`)

- Кадры и точки позы это ПДн людей в кадре, но не биометрия, так как не сопоставляются с личностью и не покидают устройство.
- Анкета, травмы, давление, беременность, боль, RPE, ограничения, причины остановок и пауз это данные о здоровье (ст. 10 152-ФЗ, ст. 9 GDPR, включая косвенный вывод), только в IndexedDB.
- Email или телефон, ник, возрастная группа, уровень, итоги и друзья это обычные ПДн на сервере ячейки с Этапа 4.
- Видимость друзьям и компании: предоставление определённому кругу лиц, а не «распространение» (уточнит юрист), согласие берётся отдельно, публичных профилей и досок нет.
- В политике прямо: «Изображение обрабатывается на вашем устройстве, не сохраняется, не передаётся и не используется для распознавания личности» (`PLAN.md:714`).
- Суд ЕС толкует данные о здоровье широко, включая косвенный вывод: C-184/20 (2022) и C-21/23 (2024) (`research/verify-backend-compliance.md:65`). Ссылка на EDPB Opinion 04/2022 не подтверждена и не используется (`verify-backend-compliance.md:65`).
- Биометрия по 152-ФЗ ст. 11 это данные, используемые оператором для установления личности. Эти ссылки на ст. 11 и COPPA взяты по знаниям модели (`verify-backend-compliance.md:66`).

### 12.8 Общие правила (`PLAN.md:736`)

Без медицинских обещаний. Аккаунты с 16 лет (в RU-ячейке см. выше). Детские профили только локально, без телеметрии, отчётов и вызовов. Политика, условия, дисклеймер, журнал согласий с версиями, для РФ отдельное согласие на обработку. Экспорт и удаление (страница удаления нужна и Google Play). Ни одного стороннего запроса.

Возраст в исследовании: проще всего 16+ везде, для РФ и Узбекистана можно 14+ с согласием родителя, но это усложняет логику (`research/compliance.md:128`).

Исключение для личных и семейных нужд (ст. 1 152-ФЗ, \*) вряд ли покроет публичный сайт с регистрацией. «Для меня и друзей» тоже обработка ПДн (`research/compliance.md:153`).

### 12.9 Записи Этапа 0 (D16, `PLAN.md:716-722`)

Единственное исключение из «точки позы не покидают устройство»: только производные числа до 30 Гц (положение и масштаб лица в ширинах лица, углы корпуса, флаги, тайминги), без массивов точек и кадров. Экран согласия в `?protocol`. Участники под псевдонимом. Файлы только владельцу, в приватном репозитории или на Drive, никогда в публичном. Записи удаляются через 90 дней после настройки порогов. Видеоклипы «живого золотого набора» только с письменного согласия, вне git, удаляются по первой просьбе и не позже Этапа 5. Если в кадр попал другой человек, отрезок удаляется. D16 в журнале: `PLAN.md:118`. Режим на паузе по слову владельца 29.10.2026.

## 13. Что можно сделать без сервера и без персональных данных

Описано в документах.

### 13.1 Состав B0 (`PLAN.md:700`)

Данные на устройстве (`profileId`, неизменяемые записи, UUIDv7, поле `v`), `progress-core`, экспорт и импорт файла, вызовы по ссылке, контент-паки на статике, zod-линтер каталога. Критерий готовности: всё работает в авиарежиме, ноль сторонних запросов. Стоимость $0 и нулевая эксплуатация до B0.5 (`PLAN.md:593`, `676`).

### 13.2 Детали по вариантам

- Вариант C, M0 и M1 без единого сервера: Dexie, журнал, `progress-core`, перенос `localStorage` прототипа (`js/storage.js`), SW при первом запуске кэширует оболочку и ML из `vendor/`, экспорт и импорт файла, контент как код (JSON-пак с версиями, `level_version` в событиях) (`plan/backend-option-c-local-first.md:340-341,349`). Гость не передаёт на сервер никаких ПДн, о госте сервер не знает ничего (`backend-option-c-local-first.md:188`).
- Судья скорости, Этап 1 «без сервера» 1-2 фокус-недели, $0: Dexie, UUIDv7 на клиенте, гость по умолчанию, кэш MediaPipe в Service Worker, `persist()`, экспорт и импорт в файл, контент как код. Три вида записей вместо полного event sourcing. XP и звёзды как чистая функция `progress-core` по сессиям. Результат сразу раздаётся друзьям (`backend-judge-velocity.md:146-149`).
- Соревнование без сервера (по желанию, 2-3 дня): вызов по ссылке, seed и целевой счёт, по желанию короткий призрак (реплей около 2-3 КБ в минуту). Друзья соревнуются через мессенджер (`backend-judge-velocity.md:150`).
- Свои треки: файл хранится в OPFS, анализ делает MIT-трекер в воркере, результат остаётся на устройстве (`backend-option-c-local-first.md:238`; `PLAN.md:236`). Аудио и признаки не отправляются никогда, в ритме v1.1 ссылка-вызов другу с отпечатком (`PLAN.md:236`). Отпечаток лишь внутри ссылки-вызова (`PLAN.md:152`).
- Режим двух устройств (телефон-камера сбоку, экран спереди): WebRTC в локальной сети, прямые адреса без TURN, сигналинг через QR-код, без сервера (`backend-judge-scale.md:34`; `PLAN.md:669`).
- Напоминания без сервера: экспорт `.ics` с повторяющимся напоминанием в календарь (вариант A, `backend-option-a-monolith.md:264`).
- Бэкап гостя без сервера: `navigator.storage.persist()`, баннер «не сохранено в облаке», экспорт в файл, приглашение установить PWA, индикатор «последний бэкап» (`backend-option-c-local-first.md:279,325`; `backend-judge-security.md:123`).
- Двухслойный экспорт: серверный `GET /me/export` и локальный (включая данные, существующие только на устройстве), кнопка «стереть всё на устройстве» (`backend-option-c-local-first.md:288`).
- Игра без регистрации как законный обход нормы о входе: норма касается только ресурсов с авторизацией (`backend-option-a-monolith.md:27`; `backend-option-c-local-first.md:197`; `PLAN.md:654`).
- Если сервер закрыть совсем, приложение продолжит работать для личного прогресса (`backend-option-c-local-first.md:321`).
- Статика, модели, аудио раздаются с собственного origin (plank.erg-team.ru, D25), Service Worker кэширует их при первом запуске (`PLAN.md:127`; `backend-judge-scale.md:26`).
- Каталог в Ф0-Ф1 обходится без Python-сервера, `ingest`-CLI в Docker на ноутбуке (ffmpeg, Beat This!, librosa) (`backend-option-c-local-first.md:230-236`). Лицензии музыки: CC0/CC BY, madmom (модели CC BY-NC-SA) и essentia.js (AGPL-3.0) названы ловушками (`research/backend.md:203`; `verify-backend-compliance.md:58`).
- Семейный режим: до 6 локальных профилей на одном устройстве, `profileId` в схеме с первой версии (`backend-judge-scale.md:30`; `PLAN.md:625`). Судья отметил, что три варианта его не моделировали.

Риск потери данных Safari через 7 дней без взаимодействия, данные могут не поместиться в OPFS на iOS (`backend-option-c-local-first.md:325,333`). IndexedDB не шифруется, на общем планшете это риск (`backend-option-c-local-first.md:289`).
- Телеметрия без сервера до B0.5: только кнопка «Отправить отчёт» (JSON-файл) (`PLAN.md:666`).
