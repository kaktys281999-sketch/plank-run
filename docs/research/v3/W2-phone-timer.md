# W2 v3. Телефон как таймер

Статус. Исследование, факты с источниками, выводов для игры нет. Дата 30.10.2026.
Происхождение. Поиск в браузере по задаче плана v3 (запрос владельца 24, HANDOFF). Продолжает `docs/research/v2/W2-engines-tech.md` §5 и не повторяет его. Что v2 уже сказал и что здесь подтверждено первоисточником, отмечено в каждом разделе.
Пометки. Факт со ссылкой. (н/п) не перепроверено первоисточником. [оценка] моя оценка. Фраза «не нашёл» значит, что подтверждения нет, а не что функции нет.

Ограничение метода. Браузерное расширение в этой сессии работало с сильными сбоями (вкладка то выпадала из группы, часть вызовов не отвечала), поэтому прочитано меньше страниц, чем планировалось. Разделы 3, 5 (частично), 7 (частично) закрыты слабо, см. раздел 9.

## 1. Screen Wake Lock

Прочитано по первоисточникам.

- Данные совместимости MDN (browser-compat-data, файл api/WakeLock.json). Chrome 84 (Android Chrome зеркалит), Firefox 126, Safari 16.4. Для Safari на iOS две записи. С 18.4 работает полностью. С 16.4 до 18.4 частично, примечание «не работает в автономных веб-приложениях с экрана Домой», ссылка на bug 254545. Источник https://raw.githubusercontent.com/mdn/browser-compat-data/main/api/WakeLock.json
- Страница MDN помечает API как Baseline 2025, только HTTPS. Запрос может быть отклонён из-за режима энергосбережения, низкого заряда или неактивного документа. Блокировка снимается сама, когда документ скрыт, поэтому при возврате её надо запрашивать заново по `visibilitychange`. Источник https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API
- Исправление для приложений с экрана Домой вышло в Safari 18.4 (31.03.2025), в заметках к релизу раздел Home Screen Web Apps, строка «Fixed Wake Lock API for Home Screen Web Apps». Источник https://developer.apple.com/documentation/safari-release-notes/safari-18_4-release-notes
- История бага. Причина в том, что WebKit включает не-экранный таймер через `idleTimerDisabled`, а у приложений с экрана Домой нет UIApplication. Работа на стороне WebKit закончена в апреле 2023, но Safari применил её только в 18.4. Источник https://bugs.webkit.org/show_bug.cgi?id=254545 (комментарии 10, 14, 32, 65).
- Подводный камень на iOS. Для `request()` нужна «transient activation» (жест пользователя). Вызов из обработчика `visibilitychange` без жеста давал NotAllowedError. Исправление WebKit от 24-25.04.2023 (263382@main). Источник https://bugs.webkit.org/show_bug.cgi?id=255363. Что именно фикс разрешил в 2026 году на устройстве, в баге не проверено (н/п).
- Обходы до 18.4 в комментариях бага (скрытое беззвучное видео, библиотека NoSleep). Сообщения противоречат друг другу, часть пишет, что видеообход перестал работать, на iPad для WebRTC не работал. Это отчёты пользователей, не проверка (н/п). Тот же баг, комментарии 35, 49, 50, 57-62.
- Android Chrome. С версии 84, без ограничений установленного приложения в данных MDN. Отдельного бага по WebAPK не искал.

## 2. Звук на iPhone

- Audio Session API в данных MDN. Safari 16.4 (iOS зеркалит) для интерфейса и свойства `type`. Свойства `state` и событие `statechange` для Safari помечены как не поддержанные. Chrome (и Android Chrome) не поддерживает, Firefox только preview. Страница MDN помечает API экспериментальным. Источник https://raw.githubusercontent.com/mdn/browser-compat-data/main/api/AudioSession.json
- Значения `type` по MDN. auto (по умолчанию), playback, transient, transient-solo, ambient, play-and-record. playback останавливает чужое воспроизведение, ambient смешивается. Источник https://developer.mozilla.org/en-US/docs/Web/API/AudioSession/type
- Спецификация. Для `AudioContext` тип по умолчанию ambient, для `HTMLMediaElement` playback, для микрофона play-and-record. Источник https://w3c.github.io/audio-session/ (разделы 5.4 и 6). Про переключатель «Без звука» спецификация не говорит.
- Про беззвучный режим. Единственное найденное прямое утверждение это запись архитектурного решения одного открытого проекта от 19.09.2026. На iOS и iPadOS Web Audio по умолчанию глушится переключателем «Без звука», медиа-элементы нет, Safari не может определить беззвучный режим. Установка `navigator.audioSession.type = "playback"` до создания `AudioContext` снимает глушение, но прерывает чужое аудио (музыку, подкасты). Автор пишет про Safari 17 и старше, расходится с 16.4 из MDN. Источник https://github.com/DrDonik/vorlese-board/blob/main/doc/adr/0004-audio-ignores-silent-mode.md. Это вторичный источник, не документация Apple (н/п). Уже была аннотация в W2 v2 §5, теперь прочитана страница.
- Safari 18.4 добавил поддержку Ogg Opus и Ogg Vorbis на iOS 18.4. Источник заметки к релизу 18.4 (ссылка в разделе 1).
- Не нашёл первоисточника ответов на вопросы про разблокировку звука первым касанием на iOS (общеизвестное правило автовоспроизведения, но в прочитанных страницах нет) и про звук при погасшем экране. Для скрытой страницы спецификация Audio Session тоже не обещает ничего про погасший экран.

## 4. Таймеры в фоне

- Из MDN (раздел 1): блокировка экрана и скрытая страница снимают wake lock, страницу надо считать неактивной, а повторный запрос делать по `visibilitychange`. Источник тот же.
- Фоновые синхронизации не поддержаны в iOS (Background Sync, Periodic Background Sync, Background Fetch) по W2 v2 §5, источник https://www.wavxsolutions.in/blog/pwa-on-ios-what-works (не перепроверено первоисточником, н/п).
- Не нашёл. Прямое утверждение о троттлинге `setTimeout`/`setInterval` в фоновых вкладках iOS и Android Chrome, решения браузерных таймерных приложений, поведение Web Audio и воспроизведения при погасшем экране. Страницы Page Visibility и заметки Chrome по таймерам не читал.

## 5. Напоминания

- Web Push на iPhone. С iOS и iPadOS 16.4, только для веб-приложения, добавленного на экран Домой, разрешение запрашивается строго в ответ на жест пользователя. Используются стандартные Push API, Notifications API и Service Worker, доставка через Apple Push Notification service, членство в Apple Developer Program не нужно, надо разрешить `*.push.apple.com` на сервере, если вы управляете адресами. Уведомления подчиняются режимам «Фокус». Поддерживается Badging API (`setAppBadge`, `clearAppBadge`). Источник https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/
- Declarative Web Push добавлен в Safari 18.4 (строка «Added support for Declarative Web Push» в заметках к релизу, раздел Web API). Источник заметки к релизу 18.4 (раздел 1).
- Требования к сообщению (каждое должно показывать уведомление, иначе разрешение отзывается) взяты из W2 v2 §5 (источник wavxsolutions, н/п).
- Что нужно на сервере. Из WebKit-блога следует, что нужен стандартный Web Push, то есть подписка с ключами, сервер отправляет сообщения на адрес подписки. Про VAPID в прочитанной странице слова нет, отдельно статью «Meet Web Push» не открывал (не нашёл подтверждения, н/п).
- Notification Triggers (отложенные уведомления без сервера). Не нашёл. Страницу совместимости `TimestampTrigger` не успел прочитать, состояние в Chrome 2026 не проверено.
- Файл календаря .ics с повтором на iPhone и Android. Не нашёл, ничего не читал.

## 6. Хранение

- Safari удаляет всё, что скрипт пишет в хранилище (IndexedDB, LocalStorage, SessionStorage, регистрации Service Worker и их кэш), после семи дней использования Safari без взаимодействия пользователя с сайтом. Приложения, добавленные на экран Домой, не часть Safari, у них свой счётчик дней, привязанный к использованию приложения, и удаление данных первой стороны не ожидается, это названо серьёзным багом. Источник https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/ (24.03.2020).
- Квоты (Safari 17 и iOS 17). Для приложений-браузеров квота одного origin до 60 % диска, общая до 80 %. Для остальных приложений 15 % и 20 %. Приложение с экрана Домой имеет те же квоты, что и браузер. Источник https://webkit.org/blog/14403/updates-to-storage-policy/ (10.08.2023). Это ближе к уточнению W2 v2, где говорилось, что у установленного приложения квота около 60 %.
- Вытеснение по принципу «давно не использовался», порядок по последнему взаимодействию или записи. Origin с активной страницей или в постоянном режиме не вытесняется. Запрос `navigator.storage.persist()` в WebKit удовлетворяется по эвристикам, пример в тексте это сайт, открытый как приложение с экрана Домой. Доступны `estimate()`, `persisted()`, `persist()` с Safari 17. Источник тот же.
- Хранилище установленного приложения отдельное от Safari (вход заново) по W2 v2 §5 (н/п).
- IndexedDB в установленном приложении. Ограничений отдельно от общего правила квот не нашёл.

## 7. Вибрация, установка, экран

- Vibration API. Данные caniuse (features-json/vibration.json). Safari на macOS и iOS Safari «нет» на всех версиях до 27.2 включительно. Chrome с 30, Android Chrome да. Firefox «да» до 128 и «нет» с 129, Firefox для Android 159 «нет». Источник https://raw.githubusercontent.com/Fyrd/caniuse/main/features-json/vibration.json. Совпадает с W2 v2 §5 («вибрации на iPhone нет»).
- Установка. На iOS через «Поделиться, На экран Домой», в iOS 16.4 «Добавить на экран Домой» стало доступно из сторонних браузеров. Сайт с манифестом, где display равен standalone или fullscreen, открывается как веб-приложение. Без манифеста это закладка, открывающаяся в браузере по умолчанию. Иконки из манифеста поддерживаются с iOS 15.4, `apple-touch-icon` имеет приоритет. Источник https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/
- Screen Orientation API входит в список функций iOS 16.4 для веб-приложений (там же, без подробностей по блокировке ориентации). Поведение блокировки поворота на iPhone не нашёл.
- Полноэкранный режим. В W2 v2 §5 сказано, что в Safari режим fullscreen манифеста не поддержан, standalone даёт окно без панели (н/п). Новых данных не нашёл.
- Установка на Android (WebAPK, `beforeinstallprompt`). Первоисточник не читал.

## 8. Самые важные факты (для резюме)

1. Wake Lock на iPhone в Safari работает с 16.4, в приложении с экрана Домой только с 18.4. Источники BCD WakeLock.json, заметки Safari 18.4, WebKit bug 254545.
2. После возврата на страницу блокировку надо запрашивать заново, на iOS до фикса 04.2023 это не давалось без жеста. Источник WebKit bug 255363.
3. `navigator.audioSession.type` есть в Safari и iOS с 16.4, `state` и `statechange` нет, в Chrome нет вообще. Источник BCD AudioSession.json.
4. По описанию одного проекта Web Audio на iOS глушится беззвучным режимом, `type = "playback"` это снимает, но прерывает чужую музыку. Источник ADR vorlese-board (вторичный).
5. Web Push на iPhone только для приложения с экрана Домой, с 16.4, через APNs без аккаунта разработчика, разрешение по жесту. Источник WebKit blog 13878.
6. Declarative Web Push в Safari 18.4. Источник заметки к релизу.
7. Семидневное удаление данных относится к сайтам в Safari, у приложений с экрана Домой свой счётчик. Источник WebKit blog 10218.
8. Квота Safari 17 и приложений Домой до 60 % диска на origin, `persist()` выдаётся по эвристикам, в том числе приложениям Домой. Источник WebKit blog 14403.
9. Vibration API нет в Safari/iOS до 27.2 включительно, в Android Chrome есть. Источник caniuse.
10. Ogg Opus и Ogg Vorbis в Safari с iOS 18.4. Источник заметки к релизу.
