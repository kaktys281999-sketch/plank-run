# Источники музыки для ритм-игры

> Research report (English). Generated by a research agent on 2026-10-19; the decision-driving claims are fact-checked separately.

## Music sources for the plank rhythm game (status as of Oct 2026)

**How this was researched:** WebFetch could not resolve almost any primary domain (spotify, apple, pixabay, audius, osu, mdn). Most findings come from search-result extracts of primary pages: Spotify developer blog and policy, Apple Performance Partners, Google YouTube policies, Jamendo help center, the Audius OML PDF and the SoundCloud docs. GitHub pages were fetched directly. Anything marked *(unverified)* rests only on secondary sources.

### 1. What a rhythm game needs from a music source
1. **Raw audio, or beat data computed in advance**, to build a beatmap: beats, downbeats, onsets, sections and energy.
2. **A playback clock we control**: Web Audio or a media element served from our own origin, or with CORS. A cross-origin stream without CORS reaches Web Audio as silence.
3. **The right to sync music to moving visuals and gameplay.** Streaming licenses do not include this. Creative Commons 4.0 explicitly treats music "synched in timed relation with a moving image" as Adapted Material.

The big streaming services fail all three. The library therefore has to be built from **music we license and control, plus music the user brings.**

### 3. Notes per category

**Streaming services are a dead end for gameplay.** Spotify is closed on three fronts, each of which is enough on its own:
- the explicit ban on games (Developer Policy, May 2025);
- removal of audio-analysis and preview endpoints for new apps (Nov 2024);
- quota rules: Feb 2026 dev mode allows 5 users and requires a Premium owner; extended quota is limited to organizations with 250k+ MAU (since May 2025).

The Web Playback SDK also needs Premium (Lite and Mini plans excluded), and commercial use reportedly needs written approval. Apple exposes no audio buffers, and the iTunes Search API forbids using previews for entertainment. YouTube forbids isolating audio and is blocked in Russia. Do not build on any of these. The most we could ever do is a "listen to this artist on X" deep link.

**License filter for any Creative Commons source.** Because CC 4.0 treats syncing music with moving images as an adaptation:
- **Exclude ND**: adaptations are not allowed.
- **Exclude NC**: any ads, subscription or IAP makes the use commercial. Jamendo's definition even includes affiliate and ad revenue.
- **Exclude SA**: share-alike could arguably attach to the synced level.
- **Keep only CC0, PD and CC BY**, plus permissive custom licenses (Pixabay, Incompetech).

For every track, store the license URL, the attribution text, and a snapshot and date of the license page as proof. Claims can arrive later, so keep a takedown and region kill-switch per track. Pixabay tracks have reportedly been registered in Content ID after the fact.

**Audius is the only free, full-track, API-first catalog whose terms are written for apps and games.** The OML gives "Music Players" a worldwide, royalty-free, sublicensable right to stream. Caveats:
- creators can disable API access, so re-check availability before every session;
- the attribution clause (§1.5) was only partly visible; read it in full;
- catalog quality is uneven and may contain unauthorized uploads, so use an in-house allowlist, not open search;
- CORS on stream URLs is unverified. Test it, and use a stream proxy only if the OML covers it.

**AI-generated music is the cheapest way to get BPM-exact, length-exact, mood-tagged tracks**, for example a 3-minute 110 BPM low-intensity "plank hold" piece. Recommendation:
- generate **offline**, curate by hand, and store as our own library; no runtime generation in the MVP;
- check each vendor's game and sublicensing clause first (ElevenLabs self-serve vs Enterprise; Mubert's "personal use" footer; Lyria terms);
- training-data litigation (Sony vs Suno/Udio) runs into 2027, so prefer vendors with licensed training data.

### 4. User uploads: formats, storage, legal

| Format | Chrome | Firefox | Safari / iOS |
|---|---|---|---|
| MP3, AAC/M4A, WAV | ✓ | ✓ | ✓ |
| FLAC | ✓ | ✓ | ✓ (Safari 11+) |
| Ogg Vorbis / Opus | ✓ | ✓ | Only iOS/macOS **18.4+**; older versions need a WASM decoder fallback |
| ALAC (.m4a) | ✗ | ✗ | ✓ |
| DRM (.m4p, Apple Music / Spotify / Yandex offline files) | ✗ | ✗ | ✗ (detect it and explain to the user) |

Pitfalls:
- **On iOS, `accept="audio/*"` is buggy** (it greys out mp3/m4a and offers the camera instead). Use explicit extensions: `.mp3,.m4a,.wav,.flac,.ogg,.opus,audio/*`.
- The Apple Music library is not reachable from the web at all. Most phone users have **no local music files**, so uploads are a power-user feature. In RU/UZ the realistic source is MP3s saved from Telegram into the Files app.
- **Memory:** a 5-minute stereo 44.1 kHz track decodes to about 106 MB of float32. Analyze in a Worker on downmixed mono at 22 kHz, then release the buffer. Cap uploads at about 50 MB or 10 minutes.
- **Storage:** keep files in OPFS or IndexedDB and call `navigator.storage.persist()`. Safari wipes script-writable storage after 7 days without interaction unless the app is installed to the home screen, so nudge users to install the PWA. Always support re-adding a file and matching it by fingerprint.
- **Analysis library licenses:** Essentia.js is **AGPL** (commercial license needed). `web-audio-beat-detector` is MIT but returns only BPM and offset. A simple spectral-flux onset detector plus a DP beat tracker is easy to write ourselves.
- **Legal design:** send the server only *derived* data: a fingerprint of the decoded PCM, the generated chart, and scores. **Never the audio.** That keeps us out of hosting-provider law entirely. If audio is ever stored or shared server-side:
  - US: DMCA §512(c) needs a registered agent (historically $6 per 3 years), a takedown process and a repeat-infringer policy.
  - Russia: Civil Code Art. 1253.1 (information-intermediary rules).
  - EU: Art. 17 DSM targets services that give the public access to large amounts of uploads; private cloud lockers are carved out.
- **Sharing charts made for uploaded songs** (the custom-map pattern from osu! and Beat Saber) is legally gray because players pair them with unlicensed audio. Ragnarock keeps custom songs private, with no leaderboards. Do the same at launch: private, or leaderboards only among friends.

### 5. The "play anything" fallback
- **Microphone mode:** music plays from another device or speaker, and the phone on the floor listens. Constraints:
  - Only **beat-grid gameplay** works (notes on predicted beats). Melodic charts are impossible without look-ahead.
  - It takes about 4–8 s to lock on, and lock is lost on breakdowns, tempo changes and quiet intros.
  - Open the mic with `echoCancellation`, `noiseSuppression` and `autoGainControl` all **off**; they are tuned for speech and gate music.
  - Our own SFX and voice cues leak into the mic, so duck them or subtract them.
  - **iOS:** opening the mic switches the page to play-and-record. Reported effects are a volume drop and output being forced to the speaker. A web page holding the audio session typically pauses Spotify or Yandex playing *on the same iPhone*, so the music must come from a second device.
  - Beat-phase error of about 20–60 ms is acceptable against the 100–250 ms body latency.
- **Desktop Chrome tab capture:** the cleanest signal, but desktop-only and a gray area. Label it "experimental" and never advertise it as "play your Spotify in our game".

### 6. How existing games solved music
| Game | Model | Lesson |
|---|---|---|
| Beat Saber | Licensed packs (e.g. Timbaland 5-track pack for $7.99, 2020); custom songs only through unofficial mods, mostly unlicensed | Mainstream music costs money for every pack |
| osu! | **Featured Artist program**: direct, non-exclusive licenses with indie artists (64 new artists in 2025); the community maps them | Cheap, scalable and community-friendly. **Copy this regionally** |
| Audiosurf 2 | User's own files plus SoundCloud streaming (from the open-API era) | Uploads work as a feature, not as the core |
| Ragnarock / Synth Riders | Licensed DLC; custom songs through an editor, private, no leaderboards | Keep UGC private |
| Supernatural / FitXR | Licensed catalogs (Merlin indie deal; Warner, Sony). FitXR cited licensing costs when moving to subscription-only | Licensing drives the business model |
| Peloton / Fit Radio | $150M publisher suit over missing sync licenses; labels sued Fit Radio | Fitness apps get sued; do not improvise |
| Rhythm Plus (web, GPL-3) | Charts built on YouTube embeds | Technically possible, but policy-fragile and blocked in RU |

### 7. Regional differences
- **Russia:**
  - Spotify gone; YouTube blocked since Feb 2026; Apple billing off since Apr 2026.
  - Yandex Music dominates but has no API.
  - **Cloudflare, Hetzner, DigitalOcean and OVH were throttled to 16 KB per asset from June 2025** (still in force today is unverified). Audio and the CDN for RU users should be hosted with a Russian or CIS provider.
  - Western B2B vendors (Epidemic, Mubert, ElevenLabs) realistically need a non-RU legal entity and payment route.
- **Uzbekistan / Central Asia:** Spotify and YouTube available. Yandex Music is active (Uzbek-language recommendations, a local awards event in Dec 2025). Local indie artists are a cheap, distinctive source to license directly.
- **Global:** every option above applies. The curated-library approach is the same everywhere; only the CDN and payment routing change.

### 8. Recommended layered strategy and what it means for the backend
1. **L0 – curated library (MVP, the default):** 40–80 tracks from CC0/CC BY, Incompetech, Pixabay, a few commissioned or AI-generated pieces, plus local indie artists under direct non-exclusive licenses. Process every track server-side:
   - ffmpeg loudness normalization to about −14 LUFS, then AAC .m4a (plus optional Opus);
   - **Beat This!** (MIT code and weights) for beats and downbeats;
   - librosa for onsets and energy;
   - all-in-one (MIT) for sections, after checking its madmom dependency and the weight license;
   - per-difficulty charts with plank constraints: about 1 lateral move per second at most, holds = static holds, density growing with level.
   
   "Auto-pick" is a recommender over our own tags (BPM band, energy, length, mood, language or region, in-app popularity and completion rate), tuned to the onboarding fitness level. "Popular" means popular inside our catalog.
2. **L1 – uploads:** local-only storage and client-side analysis in a Worker. The server stores fingerprint, chart and scores only.
3. **L2 – discovery:** Audius through a server-side allowlist. Jamendo only after a commercial quote.
4. **L3 – free mode:** mic or tab beat-following on a beat grid, labelled experimental.
5. **L4 – growth:** a regional "Featured Artist" program, AI-generated packs once terms are confirmed, and Epidemic or Artlist once there is a non-RU entity and revenue.

**Backend data model:**
- `tracks`: source, source_id, license_code, license_url, attribution, proof_snapshot_hash, proof_date, regions_allowed, status, takedown flag;
- `analyses`: algo_version, beats, downbeats, onsets, sections, energy;
- `charts`: track_id **or** fingerprint, difficulty, exercise, version. Charts are immutable; leaderboards key on chart version;
- `user_tracks`: fingerprint, duration, user-entered title. **No audio.**

**Delivery:** serve audio from a CDN with CORS. The service worker must answer Range requests (206) or Safari will not play cached media. Precache the next level's track.

**Clocking:**
- add a **latency-calibration** screen, because Bluetooth earbuds add roughly 150–300 ms;
- use `AudioContext.outputLatency` where the browser supports it;
- judge timing with wide windows, since body latency is already 100–250 ms.

### Top pitfalls
- Building on Spotify, Apple or YouTube and later discovering you are banned or have no audio.
- NC, ND or SA tracks slipping into the catalog.
- Expecting phone users to have MP3s.
- iOS microphone and audio-session side effects.
- OOM from decodeAudioData on long files.
- Safari storage eviction and the Range-request problem.
- Content ID claims on "free" tracks.
- RU throttling of Western CDNs.
- B2B vendors that cannot be paid from RU.
- Charts not versioned, which breaks leaderboards.

## Recommendation

Don't use any streaming service as the in-game music source. Spotify's Developer Policy (effective 15 May 2025) bans games outright, and Spotify, Apple Music, YouTube, Deezer and the iTunes previews all withhold raw audio or forbid this use. Without raw audio we cannot build beatmaps, and without sync rights we cannot tie music to gameplay. Ship a curated in-house library as the default: CC0/CC BY, Incompetech and Pixabay tracks, a few commissioned or AI-generated pieces, and later local indie artists under direct non-exclusive licenses, like osu!'s Featured Artist program. Analyze every library track on the server (Beat This!/librosa) and hand-tune charts per difficulty; "auto-pick" then becomes a recommender over our own BPM, energy, length and mood tags. Add uploads as a second layer: files stay on the device (OPFS/IndexedDB), analysis runs in the browser, and the server only ever receives a fingerprint, the chart and scores, never audio, which keeps us out of hosting/DMCA liability. Treat Audius (whose Open Music License explicitly covers apps and games) as an optional, curated discovery layer, and Jamendo only after a commercial quote. A microphone or desktop tab-capture "free mode" can follow any music on a beat grid, but it is experimental and on iPhone it needs a second device. If the audience includes Russia, host audio on a Russian/CIS CDN (Western CDNs have been throttled there) and expect to need a non-Russian legal entity for any paid Western music vendor.

## Open questions

- Which region is the launch target: RU, UZ/Central Asia or global? This decides CDN hosting (RU-local vs global), which vendors can be paid, and whether YouTube or Spotify even matter.
- How will the app make money (free, ads, subscription)? Any monetization rules out NC-licensed tracks and the free tier of the Jamendo API.
- Will there be a non-Russian legal entity? Epidemic, Artlist, Mubert, ElevenLabs and Google contracts and payments realistically need one.
- Should leaderboards and chart sharing exist for user-uploaded songs at launch, or stay private as in Ragnarock?
- What budget is available for commissioning or licensing tracks directly from local artists (osu!-style Featured Artist program)?
- Not verified because primary pages could not be fetched: the full text of the Audius API Terms and OML §1.5 attribution; whether Audius stream URLs return CORS headers; the current ElevenLabs Music and Lyria commercial and game clauses; the Pixabay license wording on in-app use; the current FMA API status; Musopen terms.
- Must be tested on real devices: the iOS getUserMedia audio-session effects (volume, routing, interrupting other apps), Android audio focus with other music apps, and decode memory limits on low-end phones.
