## 1. Коротко

1. **Переезд на новый стек предлагаю начать сейчас, не дожидаясь живой проверки.** Новый облик держится на атласах, анимации героя, токенах и загрузке миров по частям, в прототипе без сборки это делалось бы дважды. Пороги распознавания переносим как есть, прототип заморожен и работает. Это правка PLAN §9.5 (§2.2).
2. **Стек D12 остаётся и худеет.** Пока нет сервера и сбора данных, не нужны TanStack Query, телеметрия и библиотека переводов.
3. **Игрового движка нет.** Своё ядро sim 60 Гц плюс view, по умолчанию PixiJS 8 во всех играх, Three.js 0.186 только для Забега и боя, если главная сессия выберет настоящее 3D (игры §5).
4. **Купленные шаблоны в приложение не входят.** Они живут в закрытой лаборатории, в код переходят числа и паттерны (игры §4.3).
5. **Распознавание в воркере, логика прежняя.** Модель по умолчанию на CPU, бенчмарк выбирает GPU и уровень устройства, судейство идёт с поправкой на задержку. В v1 только режим «спереди» и одна модель лица.
6. **Экраны по мете v2.** «Начать сегодняшнее», карта, сессия как поход по миру, итоги до 30 с, достижения, коллекция, профиль, настройки и сквозной слой безопасности с кнопкой «Болит».
7. **Дизайн-система ролями.** Один файл токенов для CSS и рендера игр. Компоненты умеют и плоскую поверхность, и картинку-панель из UI-пака, потому что владелец выбрал все четыре настроения.
8. **Правило К1 делает рендер компоновщиком.** Код двигает, масштабирует и складывает готовые картинки, рисование фигур в коде игр ловит линтер.
9. **Праздники на Lottie, Rive пока нет.** Герой и Хранители анимируются спрайтами, cutout или моделью из пака.
10. **У каждого ассета паспорт в манифесте.** Купленное хранится вне публичного git, CI не пропускает файл без лицензии.
11. **CI собирает ветку `site` только из зелёного `main`, сервер тянет её вместо `main`.** Обновление ставится в меню и никогда во время сессии.
12. **Новый облик владелец видит на своём телефоне на 2-3 неделе вечеров.** Проба облика (Светлячки v2 на Pixi с указателем и главная на токенах, без камеры, 0,3-0,5 ФН) идёт сразу после Ф0 и выбора направления, параллельно Ф1-Ф2 (§11). Короткий разовый замер на телефоне стоит перед массовой закупкой арта, а не перед выбором стиля, потому что бюджеты уровней пока цели без замеров, а пререндер героя с нарядами легко съедает память (§9).

## 3. Движок игр рядом с MediaPipe

### 3.1 Потоки и цикл

Google сам пишет, что `detectForVideo` блокирует основной поток, и советует Web Worker (W2 §2). Замер 19.10 в headless Chromium это подтвердил. Поза lite в главном потоке растягивала кадр до 50-83 мс, в воркере кадр держался на 16,7 мс (F4 §4.3). Прототип считает в главном потоке (`js/pose.js:143`).

Главный поток держит оболочку React, цикл игры, HUD в DOM 10 Гц и звук, на update и render у него до 8 мс, на уровне C до 16 мс (F4 §9). Воркеры считают модель, технику и управление, поза нужна только сбоку. GPU занят рендером игры, модель уходит на GPU, только если бенчмарк это выиграл, потому что на слабых Android они дерутся за один GPU (F4 §4.9). Шаг фиксированный 60 Гц, не больше пяти шагов за кадр, затем `view.render(alpha)` (F4 §5.1). Мир и таймер идут только в фазе `active` при хорошей технике, в паузе и отдыхе sim стоит (игры §2.4). React в раунде не перерисовывается, следующая игра и её атласы грузятся в отсчёте и отдыхе.

### 3.2 Рендер

Рендер выбирается вместе с визуальным направлением (игры §5), обе ветки скрыты за `RenderHost`. В ветке 2D один `Application` PixiJS 8.22 на сессию, WebGL, WebGPU после замера, бэкенды грузятся отдельными чанками (W2 §1). В ветке 3D Забег, Тоннель и бой идут на Three.js, плоские игры на Pixi, хосты меняются только в отдыхе. Размеры Pixi и Three не проверены (W2 §6), их мерим первыми, чанк 3D может не уложиться в 260 КБ (игры §5).

### 3.3 API игровых плагинов

Контракт спец. §4.3 (`GameManifest`, `GameModule`, `GameSim`, `GameView`, F4 §5.3) остаётся. Добавления v2.

```ts
export interface RoundSpec {    // задаёт план, игра не меняет
  durationTicks: number         // от 10 до 45 с при 60 тиках
  tier: 'T1' | 'T2' | 'T3' | 'T4'
  shiftCapPerMin: number        // потолок сдвигов формы
  amplitude: number             // доля руля по форме
  finishTicks: 300              // последние 5 с без опасностей
}
interface GameManifestV2<P> extends GameManifest<P> {
  view: 'pixi' | 'three'
  bundles(world: WorldId, density: '1x' | '2x'): AssetBundleId[]
}
interface ViewContextV2 extends ViewContext {
  theme: ThemeRoles             // только роли из tokens.ts
  hero: HeroLook                // наряд героя виден в игре
}
// движок «Дорожки» (игры §3.1) это один GameModule с описанием игры
export interface LaneGameSpec {
  lanes: 2 | 3 | 5
  axis: 'x' | 'y' | 'sway'
  hysteresis: { enter: 0.6; leave: 0.4 }
  events: Array<'collect' | 'obstacle' | 'gate' | 'rail' | 'arc' | 'still'>
  view: 'chase' | 'sideScroll' | 'topDown' | 'highway' | 'arena'
  patterns: PatternSet          // из лаборатории и свои
  scoring: ScoringRules         // счёт на секунду, без длительности
}
```

- `RoundSpec` задаёт план. Трек кончается ровно на `durationTicks`, генератор не выходит за потолок и тир (игры §2.3, §3.1), тесты пределов читают тот же объект.
- `view` и `bundles` заранее говорят оболочке рендер и пакеты. `theme` даёт только роли вместо `COLORS` и `TYPES` прототипа (F4 §13.2 п. 6), `hero` показывает наряд в игре (мета §5.4).
- Голосом говорит только оболочка, игра отдаёт событие с токеном звука (F4 §5.5).

### 3.4 Детерминизм

Генератор sfc32 с сидом через cyrb128, ввод квантуется в `round(v × 127)` 30 Гц, запись `inrec/1` с хэшами каждые 300 тиков весит 2-3 КБ в минуту (F4 §5.2, §5.4). PLAN §9.2 откладывает `dmath` до публичных досок, но призрак и вызов проигрывают запись на чужом телефоне (мета §11), а V8 и JavaScriptCore расходятся в последнем бите `Math.sin` (спец. §4.2). Поэтому линтер с первого дня запрещает в `sim/` `Math.random`, `Date` и трансцендентные функции, тригонометрия живёт во view. Приёмка v1 это совпадение хэшей 10 сидов × 3 записи в Node и Chromium, WebKit до призраков v1.1.

### 3.5 Готовые шаблоны

В приложение не встраиваются (игры §4.3, §5). Phaser 3 это второй движок, удар по детерминизму и бюджету 260 КБ, его ветка закончилась на 3.90 в мае 2025 (W2 §1). Лаборатория лежит в папке вне публичного репозитория и вне iCloud. В ней шаблон, копия конвейера прототипа с экраном безопасности и `body-adapter.js`, около 0,5 дня на шаблон (игры §4.3). Адаптер переводит смену дорожки в стрелки или указатель и держит пределы оболочки (цель 20, 30 или 45 с, пауза по технике, конец после 4 с срыва, стоп-вопросы, «Болит», «Дыши», счётчик раундов дня, блок 24 часа после красных флагов). Страница отдаётся с сервера по закрытому `/lab/`, камере телефона нужен HTTPS, правка сервера только по слову владельца. В код переходят числа и паттерны, арт только по лицензии и классом `private`, а webcam-pose-runner и justmove без найденных лицензий только читаем (W2 §3).

## 4. Конвейер ввода тела

### 4.1 Путь кадра

```
CameraManager (один поток на сессию, 640×480, до 30 fps, без микрофона)
  → requestVideoFrameCallback → createImageBitmap → postMessage с transfer
  → VisionWorker face | pose (в полёте не больше кадра)
      → Analyzer (признаки → техника → калибровка → управление)
  → BodyFrame → Provider (история 2 с) → latest() для HUD, sampleAt(t) для судейства
```

Схема спец. §3 (F4 §4.1). У каждого воркера свой WASM и запрос `?task=face|pose`, иначе вторая задача падает с `ModuleFactory not set.` (F4 §4.3). Нужен WASM SIMD, а для GPU в воркере WebGL2 в OffscreenCanvas, это Safari 17 и новее. В v1 только воркер лица, около 4,1 МБ gzip на первую загрузку (F4 §4.10). Провайдеры `face`, `pose`, `keyboard`, `pointer`, `demo` (бот по сиду) и `replay` (F4 §4.4).

### 4.2 Что переносим из прототипа

|---|---|---|

| `END_AFTER 4`, `COUNTDOWN 3`, цели 20, 30, 45 | как есть, длину раунда задаёт план | F4 §12.4 |

### 4.3 Калибровка и задержка

Калибровка идёт `searching → positioning → holding → done` с кольцом 1,5 с, перекалибровка клавишей R, из паузы или голосом после трёх `moved` подряд, baseline заново в каждой сессии (F4 §4.7). Дорожки стоят на −A, 0 и +A, где A растёт с формой до амплитуды около 7 см (игры §2.3). Код считает 0,45 ширины лица за 7 см, а на синтетике сдвиг на 15 см дал лишь около 0,6 (игры §2.1). Поэтому «Чувствительность» остаётся, а в настройках появляется калибровка «Качнись влево и вправо», она масштабирует управление после анализатора и паритет не трогает.

Задержку складывают `queueMs`, `inferMs`, `analyzeMs`, `captureToResult` и `resultToPresent` (F4 §4.8), сумма видна в панели D и никуда не уходит. Игры судят по `sampleAt(tCapture − задержка)` в широком окне, на T1 ±350 мс (игры §2.2). Калибровки «Тапни в такт» и «Качнись в такт» придут с «Пульсом», основой годится `js/protocol/latency.js`.

### 4.4 Откат

| Событие | Реакция |
|---|---|
| GPU не поднялся или упал | CPU в том же воркере, событие `delegateChanged` |
| p95 выше бюджета 5 с подряд | full → lite → 30, 20, 15 Гц → камера 480×360 → режим «спереди» (F4 §4.9) |
| Камера прислала `ended` или `mute` | пауза с причиной `camera`, переподключение |
| Тело пропало | пауза, после 4 с конец интервала |
| Модель не скачалась | карточка с прогрессом по байтам, демо доступно |
| Нет WASM SIMD или module worker | только демо |

Профиль бенчмарка `{uaHash, mlVersion, model, delegate, p50, p95, tier}` лежит в IndexedDB и пересчитывается при смене версии ML или браузера.

| Достижения `/achievements` | пусто; ступени Б, С, З с полосой прогресса; скрытые силуэтом с намёком; новое подсвечено один раз |
| Коллекция `/collection` | наряды по слотам; облик объектов игр; портреты Хранителей; не получено силуэтом с источником; сундук с видимым содержимым |
| Профиль `/me` | герой и ранг; Форма только для игрока; серия, лучшая серия, копилка недель; пауза серии; экспорт и импорт |
| Друзья `/friends` | «Вставить ссылку»; вызовы отправленные и полученные; детский профиль без вызовов; компания с v1.1 |
| Ссылка `/c/` | передаточная, ничего не запускает, «Скопировать» и подсказка открыть приложение |
| Настройки `/settings/*` | камера и модель; чувствительность; звук, голос, музыка; «Меньше движения»; «Без вспышек»; крупный режим; план; хранилище и «Стереть всё»; «Авторы и лицензии» |
| Безопасность, слой поверх всего | стоп-вопросы до первой игры и при смене версии; экран-стоп «Сначала к врачу», до «Врач разрешил» только демо и дыхание; экран красных флагов с номером экстренной помощи по стране из онбординга; «Болит»; блок 24 часа после красных флагов; повтор вопросов 1-3 анкеты перед тестом и Испытанием; повтор анкеты раз в 12 месяцев, после жалобы на грудь и на новом устройстве |

Состояния из меты (мета §3, §5.1, §7, §13), маршруты из спец. §5 (F4 §6), служебные `/_dev/*` только в тестовой сборке. Тексты на «ты». Тема карты грузится после оболочки, «Начать сегодняшнее» доступна сразу, если нет блока безопасности.

Слой безопасности строже меты и повторяет PLAN §6.1 и §6.5. После красных флагов 24 часа нет никаких тренировок, ни плана, ни свободной игры, ни вызова, ни лаборатории. Следующий старт после «Я в порядке» или «Врач разрешил» и повтора вопросов 1-3 (F2 §9). Экран красных флагов говорит «Обратись за медицинской помощью» и показывает номер по стране из онбординга (D24). Россия 112 и 103, Узбекистан 103, Казахстан 112 и 103, ЕС 112, Великобритания 999 и 112, США 911, при неизвестной стране «Позвони в местную скорую помощь» и 112. Таблицу номеров вычитывает медик вместе с экранами. Экран-стоп «Сначала к врачу» включает красный маршрут анкеты (PLAN §6.1). До кнопки «Врач разрешил» доступны только демо и дыхание, отметка хранится на телефоне с датой, потом идёт бережный режим. Анкета повторяется раз в 12 месяцев, после жалобы на грудь и на новом устройстве, а до ответов на новом устройстве действует самый бережный маршрут (PLAN §6.4).

### 5.2 Потоки

```
Первый запуск
  вход → (iPhone вне «Домой») лист установки → приватность → дисклеймер и стоп-вопросы → анкета
  → (красный маршрут) экран-стоп «Сначала к врачу», дальше только демо и дыхание
  → камера и установка телефона → калибровка → руль на четвереньках на поляне «Светлячков»
  → проба на коленях 20 с → отдых 60 с с дыхательным кольцом
  → повтор вопросов 1-3 → тест на предплечьях (в бережном маршруте и при давлении его нет, старт по пробе)
  → «Твой старт», план и первая звезда → герой → .ics → карта
День плана
  карта → «Начать сегодняшнее» → разминка → (раунд ⇄ отдых) × N → заминка
  → «Как было?» → что получилось → звёзды → опыт → неделя → награды → «Дальше»
«Болит»
  стоп → что и насколько → ★ «Сделано» → бережные итоги → задания недели на отдых
Вызов
  мессенджер → /c/ «Скопировать» → приложение → «Вставить ссылку» → раунд плановой сессии
```

Итоги до 30 с (мета §3.2). Онбординг идёт по PLAN §6.1, он старше спецификаций. До первой звезды вместе с тестом не больше 7 минут, до первой игры на поляне не больше 4 минут, таблица противоречий PLAN §3.3 так заменила 4 минуты спец. M6 (F4 §11.2). Первая игра онбординга это руль на четвереньках, а не планка, после теста отдельной игры в планке нет. Если главная сессия всё же захочет игру после теста, то только после отдыха не меньше 60 с и на коленях.

Тест онбординга и Испытание формы идут на предплечьях до технического отказа, то есть до первого срыва техники, но не дольше потолка. Потолок 60 с, у Испытания на уровне 5 он 30 с, с 40 лет 45 с, у 13-15 лет и при «да» на вопрос 7 анкеты 30 с (D2, PLAN §6.1-6.2). Перед каждым тестом и Испытанием повторяются вопросы 1-3 анкеты, Испытание бывает не чаще раза в 14 дней, «Дыши, не задерживай дыхание» звучит каждые 10 с, а спереди на экране подпись «Провисание таза я не вижу, держи живот подтянутым». При давлении теста и Испытания нет. В бережных маршрутах, при беременности и у детей до отказа не держим, Испытание заменяется на 3 × 20 с с оценкой техники, а онбординг даёт старт по пробе без теста (мета §4.4). Время теста никогда не становится рекордом.

### 5.3 Правила сессии

- `--view-scale` по дистанции, 1 спереди на 0,7 м, 1,5-2 с ноутбука, 4 сбоку на 3 м (F4 §6).
- Главный элемент HUD это остаток раунда кольцом. Накопленных секунд и «лучшей планки» нет нигде (игры §7).
- Без рук. Автостарт, отсчёт голосом, автопауза, `DwellButton` 1,2 с, клавиши Space, Esc, R, D, C, цели от 64 px, без тостов (F4 §6).
- Субтитр у каждой реплики, `aria-live` не чаще раза в 5 с, не больше трёх крупных вспышек в секунду (F4 §7.6).
- Wake Lock в приложении с экрана «Домой» работает только с iOS 18.4 (W2 §5), на старых версиях подсказка про автоблокировку.

## 6. Дизайн-система

### 6.1 Роли токенов

Один источник `apps/web/src/ui/tokens.json` (PLAN §8.3 через F4 §3.2), из него `tokens.css` для `@theme` и `tokens.ts` для рендера игр. В коде только роли, скрипт CI отклоняет hex, rgb и градиенты вне токенов. Значения задаёт направление.

| Группа | Роли |
|---|---|
| Поверхности и текст | `bg`, `surface`, `surface-2`, `scrim`, `line`, `text`, `text-muted`, `text-on-accent` |
| Действие | `accent`, `accent-press`, `focus-ring` |
| Техника, зарезервированы | `state-ok`, `state-warn`, `state-broken`, `state-lost`, всегда со знаком, словом и звуком (F4 §7.2) |
| Игра | `reward`, `rare`, `hazard`, `shield`, `ghost`, `zone-tell`, опасность отличается от техники и цветом, и формой (F1 §1) |
| Прогресс | `star-on`, `star-off`, `xp`, `streak`, `rest-day`, `tier-bronze`, `tier-silver`, `tier-gold` |
| Миры и ритм | `world.sky`, `world.accent` через `data-world`, `judge-*` с миром 2 |
| Размеры | `--view-scale`, `--tap` 56 px, `--tap-primary` 64 px, `--dwell-ms` 1200, HUD 28, 56, 104 px × масштаб (F4 §7.1) |
| Форма, шрифт, движение | `radius-*`, `elev-*`, `font-display`, `font-ui`, `font-num`, `dur-1..3`, `spring-ui`, `spring-hero` |

Правило «сессия всегда тёмная» держалось на неоне (F1 §11 п. 16), теперь тему выбирает направление. Код держит светлую и тёмную тему меню и отдельный набор ролей сессии, читаемость с пола проверяет скрипт прищура (F1 §1).

### 6.2 Компоненты

У каждого компонента паспорт «где применено», без места применения он не заводится (корневой CLAUDE.md). Набор берётся из спец. (F4 §7.4) с заменами под v2. В сессии `RoundRing`, `BreathRing`, `PainButton`, `DwellButton`, `VoiceCaption`, в мете `PathMap`, `ChestCard`, `WeekStrip`, `QuestCard`, `RankBar`, `Medal`, `CollectionSlot`, `HeroView`, `PasteLinkButton`. `Surface` и `Button` бывают `flat` на ролях и `nineSlice` с картинкой-панелью из UI-пака, поля среза лежат в манифесте. `Art` выводит декоративную картинку по id слота, код страницы декор не рисует.

### 6.3 Иконки и шрифты

Иконки идут через реестр `icons.ts` с семантическими именами, в спрайт попадают только используемые, а несуществующее имя даёт ошибку типов. Так закрыты грабли корневого CLAUDE.md, где импорт несуществующей иконки lucide ронял весь рендер. По умолчанию Phosphor (MIT, около 1237 иконок, есть duotone) с уведомлением MIT рядом со спрайтом (W1 §3; F1 §6.3), мотивы достижений могут прийти из game-icons.net под CC BY 3.0 с подписью автора (мета §10). Знаки состояний ● ▲ ✕ ◌ тоже из набора.

Шрифты выбирает направление. Требования фронтенда это OFL, свой хостинг (D13), кириллица, табличные цифры и до 130 КБ gzip (F4 §9). Кандидаты перечислены в W1 §6, у популярной в казуальных играх Fredoka кириллицы нет.

### 6.4 Анимация

| Что | Чем |
|---|---|
| Переходы, листы, счётчики, звёзды | motion и CSS, с учётом «Меньше движения» |
| Праздники (сундук, ранг, победа, вехи) | Lottie через lottie-web отдельным чанком на итогах и в коллекции |
| Герой и Хранители в играх | спрайт-листы и cutout в Pixi, в ветке 3D анимация glTF из пака |
| Герой в меню | короткий лист кадров отдельно от игрового атласа, в бюджете первого экрана 60 КБ (F1 §9.5) |
| Rive, Spine | не в v1, место под ними в `HeroAnimator { play(state), setOutfit(slots) }` |

Почему Lottie. Готовые файлы можно править и публиковать при тех же условиях (W1 §4.2), плеер под MIT около 60 КБ gzip по сторонней оценке (W2 §4; F1 §6.4), подписки нет, а dotLottie требует wasm около 0,5 МБ (F1 §6.4). Rive сильнее для интерактивного персонажа (машины состояний, W2 §4), но экспорт без заставки стоит $9 за место в месяц, помесячно $17 (W1 §4.1; F4 §2), рантайм 100-140 КБ, аниматора в его редакторе у проекта нет. Spine Essential стоит $69 по скидке (W1 §4.3). Три-пять праздников v1 проще взять готовыми и перекрасить в роли при сборке.

### 6.5 Звук

Токены спец. остаются (F4 §7.6), добавляются `reward.star`, `reward.chest`, `rank.up`, `keeper.tell`, `keeper.hit`. Шины `music`, `sfx`, `voice` с лимитером, музыка под голосом −9 дБ, голос по приоритету от безопасности до похвалы и не чаще раза в 2,5 с (F4 §6). Тоны `js/audio.js` остаются заглушками, файлы приходят с обликом, например из CC0 Audio у Kenney (W1 §1.1). Тип звуковой сессии по D22, `ambient` без ритма и `playback` в «Пульсе» (F4 §8). При `ambient` переключатель «без звука» на iPhone глушит звук (W2 §5), поэтому субтитры обязательны.

### 6.6 Где К1 меняет архитектуру

1. Рендер игр компонует спрайты из атласов. Фигуры, градиенты неба, `shadowBlur` и узоры в коде игр ловит линтер, кроме отладочного скелета `?debug`. Сейчас обе игры прототипа нарисованы кодом (F1 §2.2).
2. Частицы это текстуры из пака, фоны, дорожки, арены и карта это картинки по слоям, код их только двигает.
3. Медаль собирается из рамки пака и мотива, карта из тайла, рамок узлов и точек пути по кривой (мета §10).
4. Схемы установки телефона, силуэт превью, 14 пиктограмм упражнений, пустые состояния и иконка приложения это слоты под пак или генерацию владельца. Кадры манекена со стенда идут ему вложением к промпту (К2), а не в обводку кодом (F1 §5.4).
5. Кнопки, полосы, кольца прогресса и фокус остаются CSS, это интерфейс, а не иллюстрация.
6. Имена в коде по ролям (`hero`, `guide`, `keeper`), без Искры.

## 7. Конвейер ассетов

### 7.1 Классы хранения

| Класс | Что | Где |
|---|---|---|
| `public` | CC0 (Kenney, KayKit), MIT, OFL, CC BY с подписью, Lottie Simple License, генерация владельца | `assets/` в git |
| `private` | купленные паки и всё, что из них нарезано | хранилище на маке вне репозитория и iCloud, на сервере папка вне git по пути `/p/` |
| `raw` | оригиналы генерации с C2PA, PSD паков | архив вне git (F1 §9.4) |

Craftpix запрещает раздачу исходников, GameDev Market и Envato запрещают давать пользователю извлечь ассет (W1 §1.4-1.6), а `main` за 5 минут уходит на сайт (D25). Quaternius QAL публичный git не разбирает (W1 §2.1), лицензия Casual UI Lab не прочитана (мета §10), оба пока `private`. iCloud выгружает файлы с диска (F4 §12.10). Файлы сайта браузер скачивает всегда, поэтому до покупки проверяем право на веб-приложение и отдаём купленное только атласами. Карточки «Поделиться» собираем только из `public`, иначе это похоже на экспорт арта, который Craftpix запрещает (W1 §1.4).

### 7.2 Слот и паспорт

Каждая потребность в арте это слот с ролью, местом применения, размерами, состояниями, бюджетом и источником. Для генерации главная сессия пишет английский промпт и список вложений (К2), старый `art/prompts.yaml` на неоновом STYLE_CORE не используется (мета §10).

```json
{ "id": "hero.run", "role": "hero", "usedIn": ["game:runner", "screen:collection"],
  "states": ["run", "lean-left", "lean-right", "stumble", "finish"],
  "frame": { "w": 256, "h": 256 }, "budget": { "atlas": 2048, "atlasC": 1024 },
  "storage": "private",
  "source": { "kind": "pack", "vendor": "<автор>", "license": "paid:<вендор>", "licenseSha256": "<хэш>" },
  "files": [{ "path": "/p/hero-run@2x.<hash>.webp", "sha256": "<хэш>" }],
  "attribution": null, "aiGenerated": false, "visibleWatermark": false }
```

У генерации в `source` инструмент, модель, дата, чат и id промпта (F1 §9.4). Метка идёт по правилу PLAN §8.5. Gemini на Free и Pro по умолчанию ставит видимую метку, переключатель Settings → Media watermark есть с 14.08.2026 и действует только на новые генерации (F1 §8.1). Метку нельзя вырезать, закрашивать и кадрировать, а обрезка до атласа её как раз удаляет. Поэтому в производство идут картинки из ChatGPT или из Gemini с выключенной меткой. Пока владелец не прислал скриншот настроек и тестовую картинку, Gemini только для мудбордов. Поле `visibleWatermark` заполняется при приёме, и файл с меткой в атлас не попадает. CI проверяет лицензию каждого файла сборки по белому списку, отсутствие путей `private` в git (ещё и в pre-commit), подписи CC BY и бюджеты пакета. Страница «Авторы и лицензии» собирается из манифеста с уведомлениями MIT, OFL.txt (F1 §6.2) и строкой «часть графики создана с помощью ИИ» (F1 §8.4). Без закрытого хранилища загрузчик берёт заглушки CC0, и CI купленное не нужно.

### 7.3 Обработка и бюджеты

Приём с хэшами и контактным листом, выбор владельца, альфа по паре белого и чёрного фона или ключ #FF00FF у ChatGPT, сверка с палитрой направления до ΔE2000 8 (F1 §9.3), швы тайлов, обрезка, атласы, кодирование с ориентиром AVIF около q 50 для фонов и WebP около q 80. Скриптов `scripts/art/` нет (F1 §10), они пишутся в Ф4. Героя из 3D-пака, например KayKit (CC0, glTF, W1 §2.2), в ветке 2D пререндерит в кадры стенд на three.js, который уже рендерит glTF (F4 §10.2), браузер на маке только через `chrome-safe.mjs`.

Бюджеты (F1 §9.5). Арт первого экрана до 60 КБ gzip, фон мира до 250 КБ, арт игры на Pixi сверх фона до 600 КБ, атлас до 2048², на C до 1024², декодированная графика игры до 48 МБ, на C до 24 МБ, голос до 1,2 МБ лениво.

Расчёт для героя [оценка]. 8-12 анимаций (игры §3.10) по 8 кадров 256² без обрезки дают 64-96 кадров, это 1-1,5 атласа 2048² и 16-24 МиБ, треть или половина бюджета игры ещё до нарядов, а наряд слоем на каждом кадре умножает это на число слотов. Выходы в обрезке кадров, меньшем числе кадров у редких анимаций и нарядах в игре только на одном-двух заметных слотах. Модель 3D с одной текстурой 1024² (W1 §2.2) занимает около 4 МиБ, зато дороже кадр на GPU. Это довод для развилки рендера.

### 7.4 Загрузка по частям

Пакет `shell` (оболочка, шрифты, иконки, звуки интерфейса, герой в меню) уходит в precache. `onboarding` грузится при первом запуске, `ml-face` перед первой калибровкой, `ml-pose` только в боковом режиме. `world-<N>` с фонами, темой карты, рамками узлов и портретом Хранителя грузится при входе в мир после оболочки, `game-<id>-<N>` в отсчёте и отдыхе перед первой игрой, `hero` на старте сессии, `celebrate` на итогах, голос проводника после онбординга. Плотность `@2x` для A и B, `@1x` для C. В именах хэш содержимого, кэш не устаревает. С итогов подгружается следующий уровень, прогресс показывается в байтах из манифеста.

## 8. PWA, офлайн, хранение, обновления

### 8.1 Выкладка

Сервер тянет `main` раз в 5 минут (D25), а после Vite в `main` лежат исходники, а не сайт. Предлагаемая схема.
1. Push в `main` запускает CI. Типы, Biome, тесты, сборка, бюджеты, лицензии, короткий e2e.
2. Если всё зелёное, CI собирает ветку `site`. В корне прототип до переключения, в `/app/` новое приложение с `noindex` без SW, в `/c/` передаточная страница. Хэшированные файлы прошлых сборок живут ещё 14 дней [оценка], чтобы старая оболочка не получила 404 на ленивом чанке.
3. Сервер тянет `site`, а `/p/` и `/lab/` раздаёт из своих папок вне git. Это разовая правка сервера владельца по его слову. Скрипт выкладки купленного сначала показывает список и пишет только с подтверждением.
4. После переключения в корне `site` новое приложение с SW со scope `/`, прототип в `/classic/` ещё 2 месяца (F4 §11.1).

В корне `main` остаётся `index.html` с переадресацией для копии на GitHub Pages. Красный CI до сайта не доходит.

### 8.2 Service worker

| Что | Стратегия |
|---|---|
| оболочка, чанки, шрифты, иконки | precache, навигация через `createHandlerBoundToURL` |
| `/ml/**` | CacheFirst в `ml-<версия>` с `ignoreSearch`, вне precache через `globIgnores`, иначе сборка падает на wasm 13,5 МБ (F4 §8) |
| пакеты по хэшу, включая `/p/` | CacheFirst, лишнее удаляется при `activate` |
| `/content/*.json` | StaleWhileRevalidate |
| `config.json` | NetworkFirst с таймаутом 3 с, флаги и отключение сломанной игры |
| голос и музыка | CacheFirst с ответами на Range, иначе Safari не играет кэш (F4 §8) |
| `/classic/`, `/lab/`, `/c/` | вне `navigateFallback` |

Критерий офлайна из PLAN для B0. Всё работает в авиарежиме, сторонних запросов ноль (F3 §13.1).

### 8.3 Хранение

- Dexie по F3 §4.2 и мете §16. Таблицы `records` (журнал `session_completed`, `week_closed`, `quests_rolled`, `unlock`, `equip`), `projections`, `replays`, `health`, `calibration`, `plan`, `content`, `deviceProfile`, у записей `profileId`, UUIDv7 и `v`. Проекции пересобирает чистая функция `progress-core`, журнал потом станет outbox сервера без смены схемы (F3 §4.2).
- Экспорт и перенос содержат только игровую полку, а `health`, план с секундами, калибровка и история прототипа не выходят с устройства никогда, ни в файле, ни в ссылке, ни в карточке (D4; бэкенд v2 §1 п. 3-4, §2.4, §2.7). Формат один, `plankrun-transfer/1` из бэкенда v2. Двухслойный экспорт варианта C (F3 §13.2) бэкенд v2 отклонил (§9), потому что файл может попасть в чат. На новом телефоне короткая анкета, стоп-вопросы и калибровка заново.
- Из `localStorage` `plank-run:v1` переносятся только настройки. История прототипа с секундами удержания не конвертируется, не экспортируется и в интерфейс не идёт. Сам ключ `plank-run:v1` остаётся нетронутым до следующей версии ради отката (бэкенд v2 §2.2). Стоп-вопросы задаются заново.
- `navigator.storage.persist()` просим после первой сессии или установки, WebKit выдаёт его по эвристикам, например приложению с экрана «Домой» (W5 §1.2). Статус и дата последнего экспорта видны в профиле.

### 8.4 Обновления

- SW в режиме `prompt`, тост только в меню, применение по согласию или на холодном старте, в сессии `skipWaiting` заблокирован (F4 §8). `vite:preloadError` перезагружает страницу только в меню.
- Dexie меняется через `version().upgrade()`, кэш ML версионируется отдельно.
- Пакет контента с темами недель кэшируется и работает офлайн (мета §9), задания недели сохранены записью и посреди недели не меняются (мета §8). Пакет знает минимальную версию приложения.

### 8.5 iPhone и Android

- На iOS нет запроса установки, добавленный сайт с iOS 26 открывается как приложение со своим хранилищем, отдельным от Safari (W2 §5). Отсюда `InstallSheet` до онбординга, манифест `standalone` с иконками из арта (F4 §8) и перенос файлом.
- Ссылка из мессенджера открывается вне приложения (мета §11), поэтому вызов принимается кнопкой «Вставить ссылку».
- На iPhone нет fullscreen и `vibrate` (F4 §8). На Android есть `beforeinstallprompt` (W2 §5), своя кнопка установки после второй сессии.
- Web Push работает только с экрана «Домой» с iOS 16.4 (W2 §5), в v1 напоминает календарь через .ics (мета §12).

| Уровень | Критерий, p95 в воркере | Камера и инференс | Рендер |

Уровень определяет бенчмарк, а не UA (F4 §9), частицы взяты из прежней арт-библии (F1 §1). Бюджеты по F4 §9. Игра 60 fps, на C 30, update и render до 8 мс, на C 16, long tasks в раунде ноль, «движение → экран» до 150 мс, на C 250, память до 250 МБ, JS первого экрана 180 КБ gzip, CSS 30, шрифты 130, чанк игры 260 КБ, ML 4,1 МБ спереди и 9 МБ сбоку, десять минут без падения ниже 30 fps. Это цели, на телефонах не мерили ничего (F4 §4.3, §9).

Как укладываемся. React молчит в раунде, спрайты и частицы берутся из пулов, картинки из атласов, модели из кэша, пакеты игр грузятся в отдыхе, на первом экране нет Pixi, Lottie и Three. Рядом со сторожем ML работает сторож кадра. Если кадр 5 с подряд выше бюджета, качество падает ступенями через частицы, DPR, дальний слой параллакса и рендер 30 fps.

Замер это короткий разовый шаг, а не ворота для выбора стиля. Проба облика (§11) уже идёт на телефоне владельца и показывает fps сцены Pixi прямо на экране. Перед массовой закупкой арта владелец один раз открывает `/_dev/bench` тестовой сборки на своих телефонах, около вечера [оценка]. Сцена Pixi с заданным числом спрайтов и атласами нужного размера показывает p50 и p95, ничего не отправляя, а если главная сессия рассматривает 3D, рядом идут «Забег на Pixi» и «Забег на Three.js», кадр не дольше 8 мс (игры §5, §6). По итогу уточняются плотность арта, размер атласов и развилка рендера. Выбор направления и проба облика замера не ждут. Камера и воркер лица попадают в тот же стенд в Ф2, он уточняет пороги уровней устройств.

**Подводные камни.**

- Мета и игры разошлись крест-накрест по миру 1. Мета (§5.2, §15) ставит Забег, мини-боссов с персонажем и бой, игры (§6) по умолчанию Тоннель, Испытания без персонажей и заглушку, и каждый документ ссылается на другого. Фронтенд держит состав мира данными, но список арта и порядок работ ждут одного решения главной сессии.
- С появлением сборки сервер не может отдавать `main` как есть. Пока он не тянет `site`, любая перестановка файлов в `main` за 5 минут ломает живой сайт и переадресацию GitHub Pages.
- Ни одного замера на телефоне нет, а пререндер героя с нарядами съедает память. Один атлас 2048² это 16 МиБ при бюджете игры 48 МБ, поэтому замер на телефоне владельца идёт до закупки арта.
