# Спецификация: ритм-игра «Пульс» и музыкальная система Plank Run

*Версия 1.1, 19.10.2026. Основа: `docs/research/music-sources.md`, `beatmap-audio.md`, `games.md`, `progression.md`, `frontend.md`, `design.md`, код прототипа (`js/plank.js`, `js/audio.js`, `js/games/*`) и 6 дополнительных поисков. При расхождениях главнее **проверка фактов `docs/research/verify-music-audio.md`**. Неподтверждённые факты помечены **(н/п)**, места, изменённые по проверке, — **[проверка]**.*

> **Правки v1.1 по проверке фактов** (`verify-music-audio.md`):
> 1. **allin1 убран из конвейера.** Обязательный шаг htdemucs (спорные веса), веса самого allin1 без лицензии, последний релиз 2023 года, несовместим с текущим NATTEN. Структуру трека строит свой сегментатор по энергии и новизне (§2.4, §3.3).
> 2. **Beat This! замерен.**
>    - Сервер, CPU, 4 потока, трек 4 мин: final ~12 с, small ~6 с (PyTorch), с ONNX Runtime быстрее. GPU не нужен.
>    - Браузер (WASM, 4 / 1 поток): small 14–37 с, final 28–78 с. Телефоны, по оценке, 1–3 мин.
>    - Поэтому на клиенте в MVP остаётся лёгкий MIT-анализатор. Beat This! в браузере возможен только на выбранном сегменте или через WebGPU. Многопоточному WASM нужен COOP/COEP (§3.3, §9).
> 3. **Freesound API бесплатен только некоммерчески.** CC0-эффекты скачиваем вручную в свою библиотеку (§2.1, §5.6).
> 4. **CC BY: синхронизация с геймплеем считается адаптацией**, значит обязательна пометка об изменениях по п. 3(a)(1)(B) (§2.1, §2.2, §2.5). **Pixabay:** нет режима «плеер», нет кнопки скачивания, нет публичных прямых ссылок на MP3 (§2.1, §2.4).
> 5. **Audius OML для синхронизации не подтверждён**: L2 — строго условно и не в MVP. Free-тариф (10 rps, 500k запросов в месяц) подтверждён (§1.2, §9).
> 6. **Мелкие уточнения:**
>    - модели Essentia — CC BY-NC-SA;
>    - Chromaprint в целом — LGPL-2.1;
>    - цены AcoustID и Incompetech не подтверждены;
>    - ElevenLabs Music исключает «Studio Games»;
>    - YouTube заблокирован в РФ с 10.02.2026.

## 0. Решения коротко

1. **Стриминги в игру не подключаем.** Spotify, Apple Music, YouTube и Яндекс/VK не отдают звук, запрещают игры либо заблокированы в РФ. Мировые хиты лицензировать бесплатному приложению не по силам.
2. **Три слоя музыки.** L0 — своя курируемая библиотека: по умолчанию, ручные карты. L1 — свои файлы: только на устройстве, автокарта. L2 — внешний каталог (Audius): **условно**, только после юридической проверки права на синхронизацию, не в MVP **[проверка]**.
3. **Кнопка «Выбери за меня» — главный путь, а не запасной.** Узел пути уже содержит трек. В свободной игре трек выбирает рекомендатель по уровню, длине раунда, темпу и энергии, настроению и истории.
4. **Аудио пользователя никогда не покидает устройство**, даже временно. На сервер не уходит ничего о загруженных треках, кроме анонимной телеметрии анализа.
5. **Анализ и карта разделены.** Анализ — дорогие факты о песне, считаются один раз. Карта — дешёвая детерминированная функция `(анализ, тир, окно, сид, версия генератора)`. Для библиотеки карты ручные: мастер-карта на всю песню, окна из неё вырезаются.
6. **Судим по позиции, а не по нажатию.** Окно строится во времени захвата кадра камеры с поправкой на задержку. Звук попадания играет точно в долю. По умолчанию проиграть нельзя.
7. **При срыве техники музыка не останавливается**: она приглушается («под водой»), ноты пропускаются без штрафа. Полная пауза только при выходе из кадра, сворачивании и прерывании звука.

## 1. Пожелания пользователя: что возможно

### 1.1 Честный ответ

| Пожелание | Ответ | Почему |
|---|---|---|
| «Подключить Spotify / Яндекс Музыку / YouTube» | **Нет** | Spotify Developer Policy (с 15.05.2025) прямо запрещает игры. С 27.11.2024 новые приложения не получают audio-analysis и превью. Apple MusicKit не отдаёт PCM (DRM). YouTube запрещает отделять звук и заблокирован в РФ с 10.02.2026 **[проверка]**. У Яндекса, VK и Звука нет публичного API. Без сырого звука нельзя построить карту, а без прав на синхронизацию нельзя привязать музыку к геймплею |
| «Популярная музыка» (чарты) | **Не в игре от нас** | Нужны права и на фонограмму (лейбл), и на произведение (издатель), включая синхронизацию. Это индивидуальные контракты. Peloton получил иск издателей на $150M. Бесплатному приложению это недоступно |
| «Загрузить свою музыку» | **Да** | Файл остаётся на устройстве, анализ идёт в браузере. Любой трек, который у человека есть файлом (MP3/M4A/FLAC/WAV), включая популярный, играется приватно |
| «Найти музыку через сервис» | **Частично, позже, условно** | Audius — бесплатный API полных треков с лицензией для приложений (Open Music License, 2025). Но текст OML первичным источником не подтверждён, и неизвестно, покрывает ли он синхронизацию с игрой **[проверка]**. Подключаем только после юр. проверки (§1.2, L2). Jamendo — только после коммерческой квоты |
| «Выбери за меня что-то хорошее» | **Да** | Рекомендатель по нашему каталогу и своим файлам. «Популярное» = популярное внутри Plank Run |

Текст для экрана «Почему нет Spotify?» (ссылка из пустого состояния): *«Стриминговые сервисы не разрешают играм использовать свою музыку, а сами песни защищены. Поэтому у нас своя библиотека от музыкантов, которые разрешили играть под их треки, и ты можешь добавить свои файлы: они не покидают телефон».*

### 1.2 Слоистое решение

| Слой | Что | Когда | UX |
|---|---|---|---|
| **L0 Библиотека** | CC0 / CC BY / Pixabay / прямые лицензии и заказ у артистов, ручные карты | v1 | По умолчанию. Вкладка «Для тебя» и узлы пути |
| **L1 Мои треки** | Файлы пользователя, анализ на устройстве, автокарта с меткой «авто» | v1 (бета) | Вкладка «Мои треки», кнопка «Добавить трек» |
| **L2 Каталог** | Audius через allowlist артистов, которых отобрали мы | v1.2 **условно**: только если выполнены все условия ниже, в MVP нет **[проверка]** | Вкладка «Найти», анализ как у L1 |
| **L3 Свободный режим** | Музыка с другого устройства, ноты по сетке. Микрофон или «подстучи темп» | v2, экспериментально | Пункт «Под любую музыку (эксперимент)» |

**Условия для L2 (Audius):**
1. Юрист читает полный текст OML и API Terms; первичным источником текст OML не подтверждён **[проверка]**. Главный вопрос — **право на синхронизацию с игрой**: без явного права L2 не делаем. Также нужны условия атрибуции и разрешение кэширования.
2. Тест CORS на stream-URL. Если CORS нет, прокси допустим, только если его покрывает лицензия.
3. Перед каждой сессией проверяем, что артист не отключил API-доступ.
4. Только allowlist, без открытого поиска: в каталоге бывают чужие загрузки.

Бесплатный тариф: 10 rps и 500k запросов в месяц, подтверждено README `@audius/sdk` 17.0.0 **[проверка]**. Ключ API можно держать в клиенте, bearer-токен — только на сервере.

**Блок «Где взять файлы легально»** в пустом состоянии «Мои треки»: Bandcamp (покупка, файлы без DRM), бесплатные загрузки Jamendo и Free Music Archive для личного прослушивания, OpenGameArt. И честно: «Песни из Apple Music, Spotify и Яндекса защищены и не откроются».

### 1.3 Экран «Музыка»

- **Для тебя:** крупная карточка «Сейчас сыграем» с треком от автоподбора, кнопками «Играть» и «Другой» и строкой-объяснением («112 BPM · спокойный · раунд 45 с · под твой уровень 6»). Ниже полки: «Под твой уровень», «Популярное в Plank Run» (7 дней), «Новое в сезоне», «Артист недели».
- **Библиотека:** фильтры по настроению (Бодро / Спокойно / Фокус / Эпично), темпу (медленно / средне / быстро) и длине. Строка трека: обложка, название, артист, BPM, точки сложности ●●○, значок лицензии (CC0, CC BY, ★ Артист), превью 10 с по тапу (припев), ♥.
- **Мои треки:** «Добавить трек», список со статусами: *готов*, *анализ…*, *файл удалён системой — добавь снова*, *ритм неустойчивый — режим «Поток»*. Подпись: «Файл остаётся на устройстве».
- **Без рук:** на старте узла пути трек уже выбран. Если 8 с ничего не нажато, игра стартует сама после калибровки, как в прототипе.

### 1.4 Логика «Выбери за меня»

Чистая функция `autoPick(profile, sessionPlan, catalog, history, seed)`.

**Жёсткие фильтры:**
- лицензия `live` и регион разрешён;
- есть карта нужного тира;
- в треке есть окно длины `L` с оценкой ≥ 0,5 (§4.2);
- BPM попадает в полосу уровня (§7) после свёртки темпа в 85–170;
- трек не был в последних 3 сессиях, если подходящих треков ≥ 6;
- нет дизлайка.

**Мягкая оценка** (все слагаемые 0..1):

```
s = 0.25·fitTempo   // гаусс вокруг центра BPM-полосы уровня, σ = 10 BPM
  + 0.20·fitMood    // энергия трека vs настроение (выбранное или по типу дня)
  + 0.15·quality    // байесовская доля ★★+ и дослушиваний у всех игроков (prior 20 игр)
  + 0.15·novelty    // 1 если не играл, 0.5 если > 14 дней назад, 0 если вчера
  + 0.15·affinity   // лайки и жанры пользователя, скипы (−0.5 на 30 дней)
  + 0.10·popularity // байесовские прослушивания × дослушивания за 7 дней
```

- **Настроение по умолчанию:** лёгкий день и разгрузка → «Спокойно», обычный день → «Бодро», испытание и босс → «Эпично». Выбор чипа пользователем перекрывает это.
- **Выбор:** из топ-5 сэмплируем softmax с температурой 0,3 и сидом `hash(userId, date, sessionIdx)`. Подбор стабилен, пока пользователь не нажмёт «Другой».
- **Скип:** «Другой» в первые 10 с — сигнал скипа. Дослушанный раунд с ★★+ — положительный сигнал.
- **Свои треки** участвуют в автоподборе, если их ≥ 3 и включён тумблер «Мои треки в автоподборе» (по умолчанию включён). Так «популярное» превращается в «моё любимое».

## 2. Курируемая библиотека (L0)

### 2.1 Источники и лицензии

| Источник | Лицензия | Требования | Берём? |
|---|---|---|---|
| **Прямая лицензия / заказ** у инди-артистов RU/UZ/KZ (модель osu! Featured Artists) | Наш договор «Direct-v1» | Неисключительная, бессрочная, весь мир; синхронизация с игрой; модификации (нарезка, фейды, фильтры, ноты); промо-клипы. Гарантия, что артист владеет и фонограммой, и произведением, без чужих сэмплов. Не регистрировать трек в Content ID либо внести нас в whitelist | **Да, приоритет** |
| **CC0** (OpenGameArt, например «Free Rhythm Game Music Pack 1» с BPM 122–190; Kenney; проверенные треки itch.io) | CC0 1.0 | Атрибуция не нужна, но кредитуем всегда (происхождение). На itch.io бывают «CC0?» — такое не берём | **Да** |
| **CC BY 4.0** (Incompetech / Kevin MacLeod и др.) | CC BY 4.0 | §3(a): автор, уведомление о лицензии со ссылкой, отказ от гарантий, ссылка на источник. **Пометка об изменениях обязательна** (п. 3(a)(1)(B)): п. 1(a) считает синхронизацию с движущимся изображением адаптацией, так что любой наш трек в игре — изменённый материал **[проверка]**. У Incompetech версию лицензии сверяем на странице трека: старые страницы указывают CC BY 3.0. Платная лицензия без атрибуции существует (filmmusic.io), **цена не подтверждена** **[проверка]** | **Да** |
| **Pixabay Content License** | Своя | Атрибуция не нужна. Запрещено распространение «Standalone», то есть контента по сути в исходном виде (обрезка и фильтр вкладом не считаются). Трек внутри игры, скорее всего, не standalone. Но **запрещены у нас:** режим «плеер», кнопка скачивания, публичные прямые ссылки на MP3. Аудио подаётся только внутри игровой сессии по короткоживущим подписанным URL **[проверка]**. Риск: часть авторов зарегистрировала треки в Content ID (вторичные источники, **н/п**) | **Ограниченно**: не для треков «Планки дня» и шеринга видео |
| **ИИ-генерация** (офлайн, вендоры с лицензированным обучением) | Условия вендора | Сначала проверить пункты об играх и сублицензировании. ElevenLabs Music: часть self-serve тарифов исключает «Studio Games», то есть игры, которые монетизированы **и** доступны больше чем на одной платформе. Бесплатная только-веб PWA, вероятно, не попадает под это определение; PWA плюс сторы плюс реклама — попадает, и тогда нужен enterprise-договор **[проверка]**. У Mubert — футер «personal use» | v1.1+, после юр. проверки |
| **NC, ND, SA, «personal use», неясные** | — | CC 4.0 считает синхронизацию с движущимся изображением адаптацией: ND запрещает, SA может распространиться на уровень, NC несовместим с монетизацией | **Никогда** |

**Звуковые эффекты** (звуки попаданий, тики, отсчёт) **[проверка]**: Freesound API бесплатен только для некоммерческого использования. Поэтому CC0-звуки скачиваем вручную с Freesound, Kenney и OpenGameArt в свою библиотеку, со снимком лицензии. Либо синтезируем, как в `js/audio.js`. Внешних звуковых API в рантайме нет.

**Доказательства по каждому треку:** URL лицензии, снимок страницы (PDF и SHA-256), дата снимка, текст атрибуции. Для Direct — подписанный договор. Флаги `takedown` и `regions.deny` выключают трек на клиенте при следующем `GET /catalog`.

### 2.2 UI атрибуции

- **Карточка трека, «ⓘ»:** полная строка TASL: *«„Title“ — Artist (ссылка), CC BY 4.0 (ссылка). Изменено: синхронизировано с игровым процессом, фрагмент, нормализация громкости, эффекты в игре»*.
  - **[проверка]** Для CC BY пометка «Изменено» **обязательна** (п. 3(a)(1)(B)): синхронизация — это адаптация по п. 1(a).
  - Текст хранится в `license.modificationsNote` (§2.5) и выводится всегда, когда трек под CC BY.
  - Для CC0 и Direct — по желанию.
- **Экран итогов:** одна строка мелким шрифтом «Музыка: Title — Artist · CC BY 4.0 · изменено» с переходом в карточку **[проверка]**.
- **Настройки → «Музыка и авторы»:** полный список, отказ от гарантий («Материал предоставлен „как есть“») и ссылки на лицензии.
- **Прямые артисты:** ссылка на профиль (Bandcamp, Telegram, Яндекс Музыка) — это и есть их выгода.

### 2.3 Объём v1

**Объём:** 12 треков на запуске, 40 к концу первого сезона (~3 мес.), 80 через год.

**Требования к треку:**
- оригинал 2:00–4:00;
- инструментал или вокал без внятного текста;
- ≥ 2 энергичных секции;
- стабильный темп, размер 4/4.

| Полоса BPM | v1 | Настроение | Жанры |
|---|---|---|---|
| 90–104 | 3 | Спокойно | lo-fi hip-hop, chill electronic, downtempo |
| 105–119 | 3 | Фокус | synthwave, funk-pop, электроника с дутаром/дойрой (заказ, UZ) |
| 120–134 | 4 | Бодро | house, electro-pop, инди-рок инструментал, chiptune |
| 135–150 | 2 | Эпично | cinematic-epic, trap/half-time (для боссов) |

**Состав v1 по источникам:** 4 Direct/заказ (из них 2 с центральноазиатским колоритом), 4 CC0, 4 CC BY. Pixabay — только для расширения до 40.

### 2.4 Конвейер приёма (`tools/ingest`, Python + веб-редактор)

1. **Заявка:** форма с источником и лицензией. Чек-лист: нет NC/ND/SA, автор совпадает, есть снимок страницы.
2. **Аудио:** ffmpeg → WAV 48 kHz → двухпроходный `loudnorm` до −14 LUFS, true peak −1 dBTP → AAC-LC 160 kbps `.m4a`, ~3,6 МБ на 3 мин. Один кодек для всех браузеров.
3. **Анализ:**
   - **Доли и сильные доли — Beat This!** (MIT, код и веса) без DBN. README предупреждает, что часть обучающего аудио защищена авторским правом: оценку риска делает юрист.
   - Скорость **[проверка]**: трек 4 мин на 4 vCPU — ~12 с (final) или ~6 с (small) в PyTorch, с ONNX Runtime ~7 / 4 с. Сервер только на CPU, каталог из 80 треков обрабатывается за минуты.
   - **librosa** (ISC) — onset strength и RMS.
   - **Секции — только свой сегментатор по энергии и новизне** (тот же алгоритм, что §3.3 п. 6, общий TS-код запускается в Node) **[проверка]**. allin1 не используем: в его пайплайне обязателен htdemucs со спорными весами, у собственных весов нет лицензии, последний релиз 10.2023, несовместим с текущим NATTEN. Допустим разве что как офлайн-инструмент для исследований.
   - Результат — `AnalysisV1`, та же схема, что у загрузок.
4. **Смещение декодера:** Playwright декодирует `.m4a` в Chromium, WebKit и Gecko. Кросс-корреляция с мастер-WAV даёт `decodeOffsetMs[engine]`: priming AAC — это ~44 мс, его нельзя игнорировать. Плюс в анализ кладётся `alignEnv` — огибающая онсетов первых 15 с на 100 Гц (~1,5 КБ) для проверки синхронизации прямо на устройстве (§6.1).
5. **Черновые карты:** генератор (§4.6) строит мастер-карты на всю песню для тиров T1–T3.
6. **Ручная доводка** в `tools/chart-editor` (веб): таймлайн с волной и долями, перетаскивание нот, панель линтера, разметка `cutPoints` — начал фраз, с которых может начинаться окно.
7. **Проверка:** бот-прогон (§8.3), затем живой плейтест одного раунда на тир в планке.
8. **Публикация:** неизменяемые `analysis.json` и `chart-master-{tier}.json` с хешами в именах, аудио на CDN с CORS. Для РФ — CDN у российского или СНГ-провайдера: проблемы с Cloudflare в РФ сохраняются в октябре 2026.
   - **[проверка]** Аудио отдаётся только по **короткоживущим подписанным URL**, которые выдаются при старте сессии.
   - Публичного списка файлов нет, кнопок «скачать» и режима «плеер» тоже. Это обязательно для Pixabay (запрет standalone), для остальных — единое правило.
   - Офлайн-копия лежит в Cache Storage под ключом `trackId`.

**Трудозатраты:** ~3–4 ч на трек.

## 3. Свои треки (L1)

### 3.1 Форматы

- `<input type="file" accept=".mp3,.m4a,.aac,.wav,.flac,.ogg,.opus,audio/*">`. Явные расширения обязательны: на iOS один `audio/*` глючит.
- MP3, AAC/M4A, WAV и FLAC работают везде. Ogg/Opus — Safari только с 18.4: на старых версиях показываем «Сконвертируй в MP3» (WASM-декодер, если запросы будут частыми). ALAC — только Safari.
- **DRM** (`.m4p`, офлайн-файлы стримингов) определяем по ошибке `decodeAudioData` вместе с типом контейнера и объясняем понятным текстом.
- **Пределы:** ≤ 50 МБ и ≤ 7 мин. 4 мин стерео в Float32 занимают ~92 МБ, а iOS убивает тяжёлые вкладки.

### 3.2 Хранение

- **Файл:** OPFS (`navigator.storage.getDirectory`). Пишем в воркере через `createSyncAccessHandle`: в Safari < 26 нет `createWritable`. Запасной вариант — Blob в IndexedDB.
- **Метаданные:** Dexie/IndexedDB (`tracks`, `analyses`, `charts`, `ghosts`, `stats`).
- После первой загрузки вызываем `navigator.storage.persist()`.
- **iOS:** Safari стирает данные после 7 дней без визитов, если PWA не установлена. Показываем «Установи приложение, чтобы треки не пропадали». Если файл исчез, а анализ, карты, рекорды и призраки в IDB остались: статус «добавь файл снова», повторное добавление сопоставляется по отпечатку.

### 3.3 Анализ на устройстве: свой MIT-анализатор `pulse-analysis`

essentia.js (AGPL, модели Essentia — CC BY-NC-SA **[проверка]**), aubio (GPL) и модели madmom (CC BY-NC-SA) не берём. Пишем свой анализатор на TS. Он детерминирован, не зависит от сторонних лицензий и тот же код работает в Node для тестов. Алгоритмы опубликованы, а алгоритм лицензией не защищается.

**[проверка]** Из готовых MIT-библиотек для сверки и заимствования отдельных блоков берём `@audio/beat` (3.1.0, 10.2026, живая), а не `music-tempo` (не обновлялась с 2017). Автор `@audio/beat` предупреждает, что его бенчмарк синтетический, поэтому поверка обязательна.

1. **Декодирование:** `decodeAudioData` в главном потоке; само декодирование нативное и идёт вне потока. Затем `OfflineAudioContext` на 22 050 Гц, моно, нативный ресемплинг. Float32 передаётся в воркер, исходный буфер сразу отпускаем. Если есть WebCodecs `AudioDecoder` (Chrome, Safari 26+), в v1.1 переходим на потоковое декодирование в воркере.
2. **Онсеты:** STFT 1024 / hop 220 (~10 мс), лог-мел 80 полос, spectral flux с max-фильтром по частоте (идея SuperFlux, Böck & Widmer 2013) и адаптивный порог.
3. **Темп:** автокорреляция огибающей и банк гребенчатых фильтров с лог-гауссовым априорным распределением вокруг 120 BPM. Кандидаты ×½, ×2, ×⅔ рассматриваются явно, итог сворачивается в 85–170.
4. **Доли:** динамическое программирование Ellis (2007), штраф за отклонение интервала от периода.
5. **Сильные доли:** для каждой фазы такта (0–3) складываем низкочастотные онсеты (бочка), новизну хромы на смене гармонии и совпадения с границами секций. Наивное «каждая 4-я по энергии» в бенчмарке дало F=0, поэтому сигналов три. Неуверенность (`downbeatConfidence` < 0,6) записывается и учитывается генератором (§4.6).
6. **Секции:** матрица самоподобия бит-синхронных признаков (лог-мел и хрома), ядро Фута на 8 и 16 долей. Пики привязываются к сильным долям, метки ставятся по кластерам энергии: `intro | low | mid | high | break | outro`. «Куплет» и «припев» не угадываем.
7. **Энергия и громкость:** RMS по долям (z-score), упрощённая K-взвешенная громкость. Уровень воспроизведения подтягивается к −14 LUFS, усиление не больше +6 dB, на выходе лимитер.
8. **Качество:** `cv` межударных интервалов, уверенность DP и доля тишины. Если `cv > 0,08` или уверенность низкая, `mode: 'flow'` (§4.6).

**Цель производительности:** трек 4 мин на телефоне среднего класса — ≤ 15 с. Анализ никогда не идёт одновременно с MediaPipe: только вне сессии, ML-воркер на паузе.

**Поверка:** набор из 30 треков библиотеки с разметкой Beat This! и ручной проверкой. Цель — beat F ≥ 0,85, октавных ошибок ≤ 5 %.

**Beat This! в браузере — не в MVP [проверка].** Замер onnxruntime-web WASM на треке 4 мин (серверный Xeon, 4 / 1 поток): small 14–37 с, final 28–78 с. На телефонах, по оценке, 1–3 мин. Загрузка ~3,7 МБ wasm (gzip) + ~10 МБ модели. Если MIT-анализатор не достигнет цели, в v1.2 включаем «улучшенный анализ», но:
- **только на выбранном сегменте** (окно 60–90 с ≈ 9–14 с на десктопе) или через WebGPU, где он есть;
- многопоточному WASM нужна cross-origin isolation (COOP/COEP); сначала проверяем совместимость с MediaPipe, CDN и подписанными URL аудио;
- модель качается только по явному согласию («Скачать улучшенный анализ, ~14 МБ»).

### 3.4 UX анализа

Экран с волной, которая рисуется по мере декодирования, и этапами:
1. «Читаю файл».
2. «Слушаю ритм»: точка пульсирует в найденном BPM.
3. «Ищу самые энергичные места».
4. «Расставляю ноты».

Затем **проверка на слух:** 8 с лучшего окна со щелчками метронома поверх и вопрос «Щелчки в такт?» с кнопками «Да» / «Быстрее вдвое» / «Медленнее вдвое» / «Подстучать». «Подстучать» — 8 тапов по экрану: фаза и темп пересчитываются, DP перезапускается с новым априорным темпом. Ручная правка сохраняется в анализе (`analyzer.id = 'pulse-js+user'`). Отмена доступна на любом этапе. Ошибки пишем по-человечески: «Это защищённый файл (DRM) — такие не открываются».

### 3.5 Отпечаток

- **v1:** `fileSha256` (crypto.subtle в воркере) — ключ локального кэша. Дополнительно `pcmKey` = длительность (±0,5 с) + хеш огибающей онсетов первых 30 с, квантованной до 8 бит: это ловит тот же трек, перекодированный заново.
- **v1.2:** Chromaprint через `rusty-chromaprint-wasm` (MIT, Rust-реимплементация) для ссылок-вызовов между устройствами. Оригинальный Chromaprint в целом под LGPL-2.1 (включает части FFmpeg), в клиент его не берём **[проверка]**. AcoustID не используем: он бесплатен только некоммерчески, цены платных тарифов не подтверждены **[проверка]**.

### 3.6 Приватность и авторское право — решение

- **Аудио, PCM, лог-мел и признаки не отправляются никогда**, в том числе «временно для анализа». Сервер не хранит ничего, поэтому мы не становимся хостинг-провайдером (DMCA §512, ст. 1253.1 ГК РФ). И это сильный продуктовый тезис: «музыка не покидает телефон».
- **v1:** о загруженных треках сервер не получает ничего, кроме анонимной телеметрии (длительность, время анализа, `mode`, уверенность). Рекорды по своим трекам локальные, лидербордов нет (модель Ragnarock).
- **v1.1:** ссылка-вызов другу. В ссылке `fileSha256`, `pcmKey`, длительность, параметры карты и призрак — всё без сервера. Друг добавляет свой файл. Если отпечатки не совпали, но длительность и огибающая похожи: «Похоже на другую версию — карта может отличаться».

## 4. Анализ → карта

### 4.1 Данные

```ts
interface AnalysisV1 {
  schema: 'pulse.analysis/1';
  id: string;                                   // sha256 канонического JSON
  analyzer: { id: 'pulse-js' | 'pulse-js+user' | 'beat-this' | 'manual'; version: string };
  source: { kind: 'library'; trackId: string } | { kind: 'upload'; fileSha256: string; pcmKey: string };
  durationMs: number;
  tempo: { bpm: number; cv: number; confidence: number };
  meter: 3 | 4;
  beats: number[];                              // мс, шкала декодированного PCM
  downbeats: number[];                          // индексы в beats
  downbeatConfidence: number;
  beatStrength: number[];                       // 0..1 на долю
  energy: { perBeat: number[]; perBar: number[] };   // 0..1 (нормированный z-score)
  sections: { startBeat: number; endBeat: number; label: 'intro'|'low'|'mid'|'high'|'break'|'outro' }[];
  phrases: number[];                            // индексы долей начала 4-тактовых фраз
  silence: { leadMs: number; tailMs: number };
  loudness: { lufs: number; gainDb: number };
  alignEnv: string;                             // base64 uint8, 100 Гц, первые 15 с
  mode: 'grid' | 'flow';
}

type Lane = number;                             // 0..lanes-1; позиция в u берётся из TierParams
type Note =
  | { k: 'tap';    t: number; lane: Lane; gold?: true }
  | { k: 'hold';   t: number; d: number; lane: Lane }                // рельс
  | { k: 'slide';  t: number; d: number; from: Lane; to: Lane }      // дуга, ease-in-out
  | { k: 'charge'; t: number; d: number; lane: Lane }                // «замри»
  | { k: 'rest';   t: number; d: number; cue?: 'breathe' | 'knees' | 'ready' };

interface ChartV1 {
  schema: 'pulse.chart/1';
  id: string;                                   // sha256 канонического JSON без id
  analysisId: string;
  generator: { id: 'rules' | 'authored-cut'; version: string; seed: number };
  tier: 1 | 2 | 3 | 4; lanes: 3 | 5; dda: -1 | 0 | 1;
  window: { startMs: number; endMs: number; fadeInMs: number; fadeOutMs: number; countInBars: number };
  phases: { kind: 'countin' | 'work' | 'rest' | 'outro'; startMs: number; endMs: number }[];
  notes: Note[];                                // t, d — мс от начала трека, целые; отсортированы
  stats: { moves: number; travelU: number; maxBudget10s: number; railShare: number; notesPerMin: number };
}
```

Время хранится в целых миллисекундах шкалы трека, ключи канонически отсортированы. Поэтому одна и та же карта даёт байт-в-байт одинаковый JSON на клиенте, на сервере и в тестах.

### 4.2 Окно сессии («раунд»)

Раунд — непрерывный фрагмент песни длиной 20–120 с. Внутри него фазы работы и отдыха. План сессии из прогрессии (§7) даёт длину работы `W`, отдыха `R` и число рабочих фаз.

1. **Квантование:** работа = `N` тактов, `N = round(W·BPM/240)`, допуск ±20 %. Если допуск не выходит, берём ближайшую чётную длину. Отдых — целые такты.
2. **Кандидаты:** окна, начинающиеся на `phrases` (у библиотеки — только на `cutPoints`), длина `L = countIn(2 такта) + Σфаз + outro(1–2 такта)`.
3. **Оценка:** `score = mean(energy в работе) − 0.5·mean(energy в отдыхе) + 0.2·[старт на границе секции] − 0.3·[тишина > 1 с] − 0.3·[играно в прошлый раз]`. Работа ложится на энергичные секции, отдых на брейкдауны: получается HIIT в музыке.
4. **Фейды:** вход 1 такт, выход 1–2 такта. Если трек короче плана, второй раунд идёт следующим окном того же трека или следующим треком автоподбора.

### 4.3 Типы нот

| Нота | Действие | Судейство | Тир |
|---|---|---|---|
| **Нота** (tap) | Быть в дорожке в момент доли | §5.3 | T1+ |
| **Рельс** (hold) | Держать кружок в дорожке `d` мс. Главная нота: это и есть планка | Тик на каждую долю, доля тиков в зоне | T1+ |
| **Дуга** (slide) | Плавно перейти между дорожками за 2–4 доли (T1: каждая смена дорожки — дуга) | Тик на ½ доли, расстояние до траектории с допуском запаздывания до 200 мс | T1+ |
| **Передышка** (rest) | Нот нет, можно на колени. Голос «дыши», отсчёт тактов | Не судится | T1+ |
| **Золотая** (tap+gold) | Обычная нота ×3 очков на пике энергии. **Всегда на текущем пути**, лишнего движения не требует | Промах не рвёт комбо | T2+ |
| **Заряд** (charge) | Замереть на 2–4 такта, кольцо заполняется | `std(x)` за 1 с < 0,04 u (≈ 3 мм, выше шума ~±0,02 u) | T2+ (v1.1) |
| **Стена**, вертикаль (2D) | Уйти из дорожки; позиция по `y` | — | v2 |

Боковая планка и интервалы, где сдвиг корпуса недоступен, получают **статичную карту**: центральные рельсы и заряды. Музыка и игра продолжаются, движения нет.

### 4.4 Тиры и параметры

Физическая позиция: `u ∈ [−1,2; 1,2]`. При чувствительности 1 полное отклонение 1 u ≈ 7 см сдвига корпуса (`CONTROL.frontX` в `plank.js`).

| Параметр | T1 Лёгкий | T2 Средний | T3 Сложный | T4 Мастер (v2) |
|---|---|---|---|---|
| Дорожек / позиции, u | 3 / −0,6 · 0 · 0,6 | 3 / то же | 5 / ±0,9 · ±0,45 · 0 | 5 + 2 ряда |
| Мин. интервал между сменами дорожки | 3,0 с | 1,6 с | 1,0 с | 0,8 с |
| Макс. прыжок | соседняя (0,6 u), только дугой | 2 дорожки (1,2 u), только дугой | 2 (0,9 u) | 4 (1,8 u), дугой |
| v_max / settle | 0,67 u/с / 0,4 с | 0,8 / 0,3 | 1,2 / 0,25 | 1,4 / 0,2 |
| Бюджет хода за 10 с | 1,2 u (≈ 8 см) | 2,4 u | 3,6 u | 4,0 u |
| Время подлёта ноты | 3,0 с | 2,5 с | 2,2 с | 2,0 с |
| Окно полное / точное | ±350 / ±200 мс | ±250 / ±130 | ±180 / ±90 | ±150 / ±80 |
| Зона «Хорошо» z (полуширина) | 0,30 u | 0,25 u | 0,20 u | 0,18 u |
| Плотность нот | ≤ 1,0/с | ≤ 1,5/с | ≤ 2,0/с | ≤ 2,5/с |
| Доля времени в рельсах | ≥ 50 % | ≥ 40 % | ≥ 30 % | ≥ 25 % |

**Потолок смен дорожки в минуту** задаёт физический уровень, а не тир: уровни 1–5 — 12, 6–15 — 20, 16–30 — 30. В планке на прямых руках (нагрузка на запястья) бюджет ×0,7.

**DDA** (игровая ось, ±1 шаг между раундами):
- зона z ×1,15 / ×1 / ×0,9;
- окна ±15 %;
- заполнение нотами ±20 %;
- **бюджет движения и смены дорожки DDA не трогает никогда**.

### 4.5 Бюджет движения и усталость

- `travel(t) = Σ|Δu|` в скользящем окне 10 с не больше `budget·f(t)`.
- **Внутри рабочей фазы длиной D:** `f = 1` до 0,5D, затем линейно до 0,7 к концу. Последние 2 такта фазы — без смен дорожки, финиш в центре: отдых начинается из удобной позы.
- **По фазам сессии:** k-я рабочая фаза умножается на `max(0,7; 1 − 0,07·k)`.
- **Баланс:** время слева и справа — 45–55 %, средняя позиция по времени — в пределах ±0,15 u. В крайней дорожке без перерыва не больше 4 с (T1) или 8 с (T2+). Паттерны чередуют сторону начала.
- В статистику карты пишется `travelU`. На экране итогов он переводится в сантиметры: «Корпусом ты прошёл 2,4 м».

### 4.6 Алгоритм генерации (rules-1.x)

Вход: `AnalysisV1`, `TierParams`, окно и фазы, `seed`. ГПСЧ sfc32 с сидом `hash(analysisId, tier, window.startMs, dda, generatorVersion)`. У «Планки дня» к хешу добавляется дата.

1. **Сетка ходов.** Слоты через `k` тактов, `k ∈ {½, 1, 2, 4}`: наименьшее `k`, при котором `k·barMs ≥ minMoveInterval`. Такая сетка устойчива к октавной ошибке: при 170 BPM ход раз в 2 такта, при 85 — раз в такт.
2. **Хореография по фразам.** На каждую 4-тактовую фразу выбирается паттерн, вес зависит от энергии фразы:
   - «якорь» — центральный рельс;
   - «маятник» — Ц→Л→Ц→П;
   - «ступени» — Л→Ц→П;
   - «S-дуга»;
   - «эхо» — зеркальный повтор прошлой фразы.

   На низкой энергии чаще «якорь». Ход в слоте делается с вероятностью `0,35 + 0,6·energy`.
3. **Смены дорожки → ноты.** Смена больше одной дорожки, а на T1 любая, становится дугой на 2–4 доли с началом на слоте. Остальные — нота в новой дорожке на слоте.
4. **Заполнение между ходами.** От сильной доли до `следующий ход − settle` ставится рельс. В энергичных местах рельс заменяется нотами на долях с `beatStrength > 0,55 − 0,3·energy` до потолка плотности. Если `downbeatConfidence < 0,6`, ходы ставятся на доли, кратные 2, без опоры на «единицу».
5. **Золотые:** доли выше 90-го перцентиля энергии окна, не чаще 1 на 8 тактов, только на текущем пути. **Заряды:** нарастание энергии за 2–4 такта перед секцией `high` или длинные `low`-участки, центр, ≥ 1 доли от ходов.
6. **Фазы:**
   - `countin` — 2 такта: голос «три, два, один» в доли, ноты только в центре;
   - первые 2–3 с работы — только центр;
   - `rest` — пусто, плюс `cue`.
7. **Бюджет:** проход с усталостью `f(t)`. Нарушения убираются удалением ходов с наименьшей энергией: ход заменяется продлением рельса.
8. **Линтер** (§4.7). Автоисправления: удалить ноты, затем укоротить или удалить ход. **Цели не сдвигаются никогда.** Если ошибки остались, берётся безопасный шаблон: центральные рельсы и маятник раз в 4 такта.
9. **Режим «Поток»** (`mode: 'flow'`): сетки нет. Ходы раз в 3–4 с по энергии, в основном рельсы, ноты на сильных онсетах. Звук попадания немедленный, без привязки к доле. На треке метка «Поток».

**Библиотека** (`authored-cut`): окно вырезается из мастер-карты по `cutPoints`. На границах фаз генератор вставляет `countin`, `rest` и `outro` по тем же правилам 6–7. Результат проходит тот же линтер.

### 4.7 Линтер (единый код для клиента, сервера и редактора)

Ошибки (`error`) блокируют карту:
1. **Достижимость:** для соседних целей `Δt ≥ |Δu|/v_max + settle`.
2. **Интервал** между сменами дорожки ≥ `minMoveInterval`.
3. **Прыжок** ≤ `maxJump`. Дуга длиннее одной дорожки длится ≥ `|Δu|/(0,8·v_max)`.
4. **Бюджет** за 10 с ≤ `budget·f(t)`. Смен дорожки в минуту ≤ потолка уровня.
5. **Одновременность:** у одного курсора нет двух нот на одно время.
6. **Отдых** пустой. Первая нота работы — не раньше, чем через время подлёта после конца отдыха.
7. **Плотность** ≤ потолка тира. Рельс ≥ 1 доли.

Предупреждения (`warn`): баланс Л/П, сидение в крайней дорожке, доля рельсов ниже нормы, золотая вне пиков.

Карта, которая не прошла линтер, не играется и не публикуется. Каждый отчёт сохраняется в телеметрию.

### 4.8 Детерминизм и версии

- `generator.version` — semver. **Любое** изменение результата на эталонных анализах требует поднять версию: это ловит golden-тест.
- Лидерборды, призраки и вызовы привязаны к `chart.id`. Старые рекорды остаются на старом `id` с пометкой «прошлая версия карты».
- Сервер проверяет присланный результат: он воспроизводит карту по `(analysisId, параметры, seed, version)` и сверяет `id`.

## 5. Геймплей

### 5.1 Экран

- **Телефон, портрет** (основной случай: телефон на полу ~60 см, фронтальная камера):
  - поле на всю ширину;
  - дорожки вертикальные, ноты летят сверху вниз;
  - линия удара на 78 % высоты, кружок на ней;
  - сверху одна главная цифра (кольцо оставшегося времени фазы) и комбо;
  - очки мелко, статус техники полосой по краю (`design.md`).
- **Альбом и ноутбук:** поле по центру шириной ≤ 60 % (5 дорожек читаются лучше), HUD слева. На ноутбуке в боковом режиме (v2) масштаб `--view-scale` 2–4.
- **Объекты:** нота ≥ 0,7 ширины дорожки; подпись оценки ≥ 42 px (комфортная подпись с 0,7 м); не больше 3 типов объектов одновременно на T1.

### 5.2 Кружок и подлёт

- **Кружок — «Искра»:** радиус 0,35 ширины дорожки, свечение по цвету техники (мятный / янтарный / коралловый), шлейф.
- **Позиция на экране:** One Euro (уже в `plank.js`), экстраполяция на 60 мс с ограничением и визуальный магнит в пределах 30 % от центра дорожки. **Судейство идёт по сырой отфильтрованной истории, без магнита и предсказания.**
- **Подлёт:** скорость постоянна в рамках карты (время подлёта из §4.4), от BPM не зависит. Линии тактов прокручиваются вместе с нотами. Рельс — светящаяся полоса, дуга — кривая между дорожками с точками тиков.

### 5.3 Судейство по позиции

- **История:** у каждого `BodyFrame` время захвата `t_cap` (rVFC `captureTime`, где он есть, иначе время прихода минус калиброванная константа). Время песни для сэмпла: `τ = S(t_cap) − O_body` (§6.1). Расстояние `d = |x − u_lane|`.
- **Пороги по z тира:** «Идеально» d ≤ 0,4z, «Отлично» d ≤ 0,7z, «Хорошо» d ≤ z, иначе «Мимо».
- **Нота во время T:**
  1. берём лучший (минимальный) `d` среди сэмплов из **точного** окна `[T ± точн]`. Если это ≥ «Хорошо», это и есть оценка;
  2. иначе берём лучший `d` в **полном** окне и понижаем на ступень. «Идеально» → «Отлично», «Хорошо» остаётся «Хорошо».
- **Ранняя фиксация:** как только в точном окне пришёл сэмпл «Идеально», оценка ставится сразу, лучше уже не будет. Подпись появляется через ~150 мс после доли, а не после закрытия окна.
- **Рельс:** голова судится как нота. Тик на каждой доле засчитывается, если в `[тик ± точн]` есть сэмпл с `d ≤ 1,2z`. Провалы трекинга < 150 мс считаются «в зоне». Итог: ≥ 95 % тиков — «Идеально», ≥ 80 % — «Отлично», ≥ 50 % — «Хорошо». Над рельсом метка «Держишь!».
- **Дуга:** тики на ½ доли. Расстояние до траектории `path(τ − lag)`, где lag выбирается в [0; 200 мс], зона 1,3z.
- **Фреймы без лица** (`present=false`) не судятся. Если пропуск длиннее окна, нота «пропущена» без штрафа (§5.5).

### 5.4 Комбо и очки

- **Комбо:** «Идеально» и «Отлично» дают +1, «Хорошо» замораживает, «Мимо» сбрасывает. Рельс и дуга дают +1 за каждые 4 засчитанных тика. Промах по золотой не сбрасывает.
- **Множитель:** ×2 с 10, ×3 с 25, ×4 с 50. На ×4 включается «В ударе»: аура, шлейф и шиммер на звуках попаданий. Саму музыку не меняем.
- **Очки:** нота 100 × {1; 0,8; 0,5; 0} × множитель. Тик рельса или дуги — 10. Полный заряд — 300. Золотая ×3.
- **Точность:** взвешенная сумма оценок / максимум по судимым нотам; пропущенные (срыв техники, пауза) не входят.
- **Звёзды:**
  - ★ — раунд дойден в планке, техника ≥ 80 % рабочего времени;
  - ★★ — точность ≥ 70 %;
  - ★★★ — точность ≥ 90 % или все рельсы ≥ «Отлично».
- **No-fail по умолчанию.** Полоса жизни есть только в режиме «Испытание» (v1.1).

### 5.5 Срыв техники, пауза — решение

| Событие | Музыка | Карта | Оценка |
|---|---|---|---|
| Срыв техники ≤ 4 с (`formOk=false`) | Играет, −6 dB, lowpass 800 Гц («под водой»), рампа 150 мс | Идёт дальше, ноты тускнеют | Ноты «пропущены», не судятся, комбо не рвётся. Голос с подсказкой |
| Срыв > 4 с (как `END_AFTER` в прототипе) | Как выше | Текущая рабочая фаза заканчивается и становится отдыхом. Следующая фаза идёт по плану | Оставшиеся ноты фазы «пропущены» |
| 3 таких срыва подряд | Выход: fade-out на ближайшей сильной доле | Раунд закончен, «техника устала» — это не провал | Итоги по сыгранному |
| Нет лица > 2 с, `visibilitychange`, `AudioContext` interrupted, кнопка паузы | **Полная пауза** (§6.4) | Стоп | — |

Почему не «музыка играет, карта стоит»: ноты разойдутся с музыкой, и ритм-игра потеряет смысл. Почему не стоп музыки на каждый срыв: в планке срыв короткий и частый, а постоянные остановки рвут поток и раздражают.

### 5.6 Звук попадания в долю

Обратная связь звучит в такт, даже когда тело опаздывает.

- **Предсказательный звук:** планировщик (§6.1) за 120 мс до доли T смотрит на последний сэмпл. Если игрок уже в зоне «Хорошо» (а в позиционной игре так почти всегда, игрок ждёт в дорожке), звук ставится на ctx-время доли (`startCtx + (T − window.startMs)/1000`). Он звучит вместе с долей в музыке: задержка вывода у музыки и у звука общая, отдельная поправка не нужна. Если оценка потом окажется «Мимо», ещё не начавшийся источник останавливается `stop()`, а начавшийся — редкая и терпимая ошибка.
- **Поздний вход** в окне: звук на ближайшую 1/8 сетки, тише.
- **Рельс:** мягкий тик на каждую долю, пока игрок в зоне.
- **Набор звуков:** перкуссионные (клэп, шейкер, «блик»), без высоты тона, чтобы не спорить с тональностью. Для библиотеки дизайнер выбирает набор под трек. Источник — свои CC0-файлы, скачанные вручную, или синтез. Freesound API не используем: он только некоммерческий **[проверка]**. Промах беззвучен; ошибочный звук немузыкален и раздражает.

### 5.7 Обратная связь и итоги

- **Попадание:** крупная подпись в дорожке у линии удара (Идеально — золото, Отлично — мятный, Хорошо — циан, Мимо — серый), вспышка дорожки, частицы. Не больше 3 вспышек в секунду (WCAG 2.3.1). Фон пульсирует только на сильных долях. Без reduce-motion есть частицы, с ним — только смысловые анимации.
- **Итоги:** звёзды; очки; точность; счётчики оценок; макс. комбо; время в планке с хорошей техникой; «корпусом прошёл N м»; сравнение с призраком лучшего забега; «Было тяжело?» с тремя кнопками (`progression.md`); строка атрибуции; ♥ и 👎 треку; кнопки «Ещё раз», «Дальше», «Другой трек».

## 6. Синхронизация и задержка

### 6.1 Часы

- Один `AudioContext` на приложение. Трек декодируется один раз. Нужное окно с запасом ±2 такта копируется в отдельный `AudioBuffer`, полный буфер отпускается. Окно играет `AudioBufferSourceNode`, запуск в точный момент `startCtx`.
- **Граф:** `source → musicGain → duck → lowpass(обход 20 кГц) → master → destination`, `sfx → sfxGain → master`. Безопасный лимитер `DynamicsCompressor` на master.
- **Слышимое время песни в момент `p` (performance.now):**

  `S(p) = ctxTime(p) − startCtx + window.startMs/1000 − L_out − O_audio`

  - `ctxTime(p)` берём из `getOutputTimestamp()` (сглаживание медианой по 10 замерам, проверка на скачки) или из `currentTime` с поправкой.
  - `L_out` = `outputLatency` (Chrome 102+, Firefox 70+, Safari 18.4+), иначе `baseLatency`.
  - `O_audio` — калиброванный остаток, может быть отрицательным.
- **Рендер** рисует ноты в `S(rAF timestamp + 1 кадр)`. **Судья** использует `S(t_cap) − O_body`. `<audio>.currentTime` как часы не используем.
- **Планировщик:** тик 25 мс, lookahead 120 мс. Он ставит щелчки метронома, звуки попаданий, тики рельсов и автоматизацию приглушения.
- **Выравнивание библиотеки:** после декодирования первые 15 с кросс-коррелируются с `alignEnv` (поиск ±100 мс). Найденный сдвиг заменяет `decodeOffsetMs`, если расходится с ним больше чем на 10 мс. Это страхует от разной обработки priming у AAC/MP3-декодеров.

### 6.2 Калибровки: обе без планки

1. **«Тапни в такт»** (звук): человек сидит с телефоном в руке. 16 щелчков при 100 BPM, тап по экрану на каждый.
   - `O_audio = median(tap − click_audible)`, выбросы отсекаются через MAD.
   - Задержка касания 10–30 мс попадает в замер, это допустимо.
   - Есть ручной ползунок с шагом 5 мс и визуальный вариант «совмести вспышку со щелчком» для людей, которым тапать неудобно.
2. **«Качнись в такт»** (тело и камера): телефон стоит как в игре, человек сидит или стоит на коленях лицом к экрану. Под метроном 40 BPM он 12 раз качается влево и вправо, по одной стороне на щелчок.
   - Измеряется время **крайних точек** `x(t)`: в позиционной игре важно «быть на месте в долю».
   - `O_body = median(t_extreme − click)` с MAD.
   - Так измеряется задержка камеры (если нет `captureTime`) вместе с привычкой человека опаздывать или опережать.
   - Пределы ±300 мс. Если разброс больше 120 мс: «Попробуем ещё раз, медленнее».
3. **Тихая подстройка:** в первых 8 тактах каждого раунда собирается медиана опережения или запаздывания попаданий. `O_body` сдвигается не больше чем на ±30 мс за сессию и сохраняется.

Калибровки хранятся по профилю вывода: «Динамик», «Проводные», «Bluetooth» и отдельно по устройству. Профиль выбирается чипом на экране музыки. Подсказка: `outputLatency > 80 мс` → «Похоже на Bluetooth».

### 6.3 Bluetooth

- Bluetooth добавляет 150–300 мс, задержка плывёт (AirPods: ~215 мс при подключении, потом ~155 мс), а iOS занижает `outputLatency`. Эти цифры проверка фактов не подтверждала (**н/п**, мерить на устройствах), но калибровка нужна в любом случае.
- **Срабатывание:** на событие `devicechange` или скачок `outputLatency` больше 40 мс между сессиями игра предлагает быструю перекалибровку (8 тапов).
- **Дрейф внутри сессии:** `outputLatency` опрашивается раз в 2 с. Изменения применяются плавно, не быстрее 10 мс/с, и только на границах тактов.
- **Совет на экране:** «Точнее всего — динамик телефона или наушники с проводом». Микрофон не запрашиваем никогда: на iOS это переводит AirPods в HFP-моно и делает Web Audio тише.

### 6.4 Пауза и продолжение

- **Пауза:** запоминается `S`, источник останавливается `stop()`. `AudioContext` не приостанавливаем, кроме сворачивания вкладки: так нет повторной разблокировки на iOS.
- **Продолжение:**
  1. новый источник стартует с `сильная доля ≤ S` минус 1 такт;
  2. 1 такт отсчёта голосом и метрономом под музыку;
  3. ноты до точки паузы не судятся повторно и показываются призрачными.
- **Если `AudioContext` в состоянии `interrupted` или `suspended`** (звонок, Siri): экран «Нажми, чтобы продолжить», `resume()` в обработчике жеста.

### 6.5 iOS

- `AudioContext` создаётся и `resume()` вызывается в нажатии «Начать». В том же нажатии «прогревается» speechSynthesis (уже есть в `audio.js`).
- До старта `navigator.audioSession.type = 'playback'` (Safari 16.4+), чтобы беззвучный переключатель не глушил игру. Поведение проверить на устройстве (**н/п**).
- `getUserMedia({ video: true, audio: false })`.
- Декодирование строго последовательное, по одному файлу. Частоту дискретизации контекста не задаём.
- Голосовые подсказки по возможности только в отдыхе и отсчёте, музыка на них приглушается на −8 dB.
- Без `outputLatency` (< 18.4) калибровка обязательна. Wake Lock в установленной PWA работает с 18.4.

## 7. Связь с прогрессией

Игровая и физическая оси раздельны (`progression.md` §9). Уровень задаёт тир, длину раунда и потолки движения. DDA меняет только окна, зоны и заполнение нотами.

| Уровни (блок) | Тир / дорожки | Раунд | Рабочие фазы | BPM автоподбора | «Пульс» в пути |
|---|---|---|---|---|---|
| 1–5 (A, колени) | T1 / 3 | 20–45 с | 1 фаза 10–30 с + хвост-передышка | 90–112 | Узлы-знакомства: «Нота», «Рельс», «Дуга» по одной |
| 6–10 (B) | T1, по DDA T2 / 3 | 30–60 с | 2–3 × 10–20 с | 95–120 | С 8-го уровня шаблон «Ритм»: интервал = N тактов |
| 11–15 (C) | T2 / 3 | 45–90 с | 2–3 × 20–40 с. Боковые — статичная карта | 100–128 | + золотые, заряды |
| 16–20 (D) | T2 или T3 / 3–5 | 60–120 с | 30/15 и т. п., фраза = фаза | 105–135 | T3 открывается после ★★ на 3 треках T2 |
| 21–30 (E–F) | T3 / 5 | 60–120 с | EMOM: минута начинается с фразы | 110–150 | T4 (v2) после ★★★ на T3 |

- **Решение о сложности** по итогам раунда (цель 65–85 % успеха в окне из 20 событий):
  - промахи совпадают с флагом техники → причина физическая, DDA не трогаем;
  - промахи при хорошей технике → DDA −1;
  - серия ★★★ → DDA +1 и вопрос «Попробуешь „Сложный“?».
- **Открытия:**
  - треки привязаны к мирам пути (Город — synthwave, Космос — электроника, Океан — lo-fi), по 3–4 трека на мир;
  - сезон добавляет 8–10 треков;
  - «Мои треки» открываются после первого пройденного узла «Пульса»: сначала человек учится на ручных картах;
  - «Артист недели» открыт всем;
  - за деньги ничего не открывается.
- **Призраки.** Запись забега:

  ```ts
  { schema: 'pulse.ghost/1', chartId, hz: 30,
    x: Int8Array /* −1,2..1,2 → −127..127 */, form: Uint8Array /* биты */,
    judg: Uint8Array, score, at }
  ```

  Это ~3–6 КБ/мин. Полупрозрачный кружок лучшего и последнего забега на той же карте (`chartId`) и разница очков вживую. Для библиотеки призраки синхронизируются с сервером (реплей уже есть в `backend.md`), для своих треков хранятся локально. Через ссылку-вызов (v1.1) призрак уходит другу вместе с параметрами карты. «Планка дня» — общий сид дня на треке библиотеки.

### 8.3 Тестирование

1. **Golden-карты:** 20 эталонных анализов (10 библиотечных и 10 синтетических) × 3 тира. Снимки `ChartV1` в репозитории. Расхождение при той же `generator.version` роняет CI.
2. **Свойства** (fast-check, MIT): на случайных анализах (темп 60–200, сбитая сильная доля, тишина, `flow`) любая сгенерированная карта проходит линтер, детерминирована и укладывается в бюджет.
3. **Боты на синтетическом сигнале** — модель тела: задержка 150–250 мс, `v_max`, шум ±0,02 u, дрейф усталости.
   - «Идеальный» бот должен набрать ≥ 95 % «Отлично»+ на T1–T3. Это проверяет честность окон.
   - «Ленивый» (v_max ×0,6) — ≥ 70 % на T1.
   - «Случайный» — ≤ 35 %. Это проверяет, что игра требует движения.
4. **Анализатор:** F-мера долей и сильных долей и октавные ошибки на поверочном наборе (§3.3). Время анализа на эталонных устройствах.
5. **Задержка:**
   - Playwright с фейковой камерой (`.y4m` с лицом, качающимся синхронно со щелчками в WAV): сквозная проверка `O_body` ±30 мс;
   - ручной протокол на iPhone SE/12 и слабом Android: съёмка 240 fps второй камерой, расхождение вспышки и щелчка с Bluetooth и без;
   - кросс-корреляционный тест `decodeOffsetMs` для трёх движков в CI.
6. **Ручной плейтест** каждого тира в настоящей планке перед релизом трека.

## 9. Риски и MVP

### 9.1 Риски

| Риск | Мера |
|---|---|
| NC/ND/SA или «CC0?» просочились в каталог; Content ID у Pixabay или у артистов через дистрибьюторов | Чек-лист приёма, снимки лицензий, kill-switch по треку и региону, пункт о Content ID в Direct-договоре, Pixabay не для шеринга |
| **[проверка]** Нет пометки об изменениях у CC BY; Pixabay-трек выглядит как standalone-раздача | Обязательный `modificationsNote` в схеме и линтер каталога. Аудио только по подписанным URL внутри сессии, без «плеера» и скачивания |
| **[проверка]** Beat This! обучен на частично защищённом аудио (README) | Юр. оценка до продакшена. На клиенте всё равно свой MIT-анализатор, Beat This! — только сервер для каталога |
| **[проверка]** Тяжёлая зависимость без лицензии (allin1, веса htdemucs) | Исключены, структура строится своим сегментатором |
| Автокарты своих треков хуже ручных, ошибки темпа | Проверка на слух со щелчками, ×2/÷2, «подстучать», режим «Поток», метка «авто», Beat This! в браузере в v1.2 |
| OOM при декодировании на iOS | Пределы 7 мин и 50 МБ, последовательное декодирование, отпускать буферы, `AudioDecoder` в v1.1 |
| Разный priming декодеров сдвигает карту на 20–50 мс | `decodeOffsetMs` и выравнивание по `alignEnv` на устройстве |
| Bluetooth: дрейф, заниженный `outputLatency` | Профили вывода, перекалибровка на `devicechange`, плавная подстройка, широкие окна |
| Поздние подписи оценок раздражают | Ранняя фиксация и предсказательный звук в долю |
| Карта выше физических возможностей, нагрузка растёт незаметно | Линтер с бюджетом, потолки уровня, DDA не трогает движение, усталость `f(t)` |
| Кивок головой вместо сдвига корпуса | Только ось x в v1; вертикаль — в v2 с проверкой масштаба лица |
| Safari стирает OPFS | Просьба установить PWA, `persist()`, повторное добавление по отпечатку |
| Анализ во время игры отнимает CPU у MediaPipe | Анализ только вне сессии |
| Audius: текст OML и право на синхронизацию не подтверждены, CORS не проверен, в РФ может не открываться **[проверка]** | L2 не в MVP. Строго условно: без юр. подтверждения права на синхронизацию не делаем вовсе |

### 9.2 MVP-срез

**v1 (запуск «Пульса»):**
- Фронтальный режим, ось x, 3 дорожки (T1–T2) и 5 дорожек (T3).
- Ноты: Нота, Рельс, Дуга, Передышка, Золотая.
- Библиотека 12 треков с ручными мастер-картами, автоподбор, атрибуция.
- Свои треки (бета): MP3/M4A/WAV/FLAC, OPFS, `pulse-analysis`, проверка на слух, режим «Поток», только локальные рекорды.
- Калибровки «Тапни» и «Качнись», профили вывода.
- No-fail, звёзды, призрак своего лучшего забега, приглушение при срыве, полная пауза.
- Линтер, golden-тесты, боты.

**v1.1:**
- Заряды, режим «Испытание» с полосой жизни.
- Ссылки-вызовы (своё аудио у друга по отпечатку).
- Потоковое декодирование через WebCodecs, ИИ-треки после юр. проверки, библиотека до 40.

**v1.2:**
- Audius L2 — **условно**, только если пройдены все условия §1.2 **[проверка]**.
- Beat This! small в браузере как «улучшенный анализ» по согласию: только на выбранном сегменте или через WebGPU, после проверки COOP/COEP **[проверка]**.
- Chromaprint (`rusty-chromaprint-wasm`).

**v2:**
- Сетка 3×2 с вертикалью, стены, T4.
- Боковой режим (дорожки по глубине, стерео-подсказки, касание плеча как золотая нота).
- Свободный режим L3 (микрофон или «подстучи» под музыку с другого устройства), сезоны с Featured Artists.
